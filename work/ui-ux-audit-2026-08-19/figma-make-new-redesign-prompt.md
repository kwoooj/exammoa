# Figma Make 신규 전면 개편 프롬프트

아래 구분선 사이의 내용을 그대로 복사해 Figma Make에 입력한다.

---

한국의 자격증·어학 시험 정보를 찾고, 접수 기간·시험일·발표일을 확인한 뒤 공식 기관 사이트로 이동할 수 있는 반응형 웹 서비스 **시험모아**를 처음부터 새로 디자인하고 작동하는 고품질 프로토타입으로 만들어줘.

## 가장 중요한 전제

- 기존 시험모아 화면, 이전 생성 이미지, 기존 레이아웃, 기존 디자인 토큰과 색상 논의를 모두 참고하지 말고 빈 캔버스에서 새로 설계한다.
- 기존 화면을 개선하거나 리스킨하는 작업이 아니다. 사용자 목적과 아래 기능 요구사항만 유지하고 정보 구조와 시각 체계는 새로 제안한다.
- **관심 시험 일정은 캘린더 화면에 함께 배치하지 않는다.** 관심 시험은 독립된 페이지에서 목록과 일정 비교표로 관리한다.
- 캘린더 화면에는 관심 시험 섹션, 관심 시험 표, 즐겨찾기 필터, 관심 시험 전용 패널을 넣지 않는다.
- 로그인과 서버 계정은 없는 MVP다. 관심 시험 저장은 브라우저 로컬 저장을 가정한다.
- 향후 취득 자격 관리 기능이 추가될 예정이지만 이번 MVP 화면에는 노출하지 않는다.

## 제품이 해결할 문제

시험 정보는 여러 기관에 흩어져 있고 같은 시험도 접수, 추가접수, 시험, 발표 날짜가 멀리 떨어져 있다. 사용자는 다음 질문에 빠르게 답할 수 있어야 한다.

1. 지금 접수할 수 있는 시험은 무엇인가?
2. 관심 있는 시험의 다음 일정은 언제인가?
3. 특정 날짜에는 어떤 시험 일정이 겹치는가?
4. 한 시험의 접수 기간, 시험일, 발표일은 어떤 순서인가?
5. 공식 접수처나 공식 공고로 어디에서 이동하는가?

## 핵심 사용자 흐름

1. 홈에서 시험명 또는 시행기관을 검색한다.
2. 검색 결과를 필터링하고 시험 상세로 이동한다.
3. 상세에서 다음 일정과 전체 일정표를 확인한다.
4. 공식 시험정보 또는 원서접수 사이트로 이동한다.
5. 필요하면 시험을 관심 목록에 저장한다.
6. 관심 시험 페이지에서 저장한 시험들의 접수·시험·발표 일정을 표로 비교한다.
7. 날짜 중심으로 탐색할 때는 별도의 전체 시험 캘린더를 사용한다.

## 정보 구조와 라우트

다음 다섯 화면을 데스크톱과 모바일로 완성한다.

- `/` 홈
- `/exams` 시험 찾기
- `/exam/정보처리기사` 시험 상세
- `/calendar` 전체 시험 캘린더
- `/favorites` 관심 시험

전역 내비게이션은 `시험 찾기`, `시험 캘린더`, `관심 시험`, `서비스 소개`로 구성한다. `내 자격`, 로그인, 프로필, 알림 센터는 이번 MVP에 만들지 않는다.

## 디자인 방향

한국어 정보 서비스로서 신뢰감이 있으면서도 공공기관 사이트처럼 낡아 보이지 않는 완전히 새로운 시각 체계를 제안한다.

원하는 인상:

- 현대적이고 정돈됨
- 오래 보아도 피로하지 않음
- 시험명과 날짜가 먼저 읽힘
- 정보량이 많아도 복잡해 보이지 않음
- 전문적이지만 딱딱하지 않음
- 모바일에서도 빠르게 훑을 수 있음

색상, 타이포그래피, 간격, 모서리, 컴포넌트 스타일은 처음부터 새로 정의한다. 기존의 코발트 블루, 보라색, 오커색 또는 이전 시안의 팔레트를 이어받지 않는다.

새 팔레트 원칙:

- 기본 배경과 본문 대비는 WCAG AA를 만족한다.
- 주요 행동색은 하나만 선정한다.
- 캘린더의 일정 구분색은 낮은 채도와 충분한 명도 차를 사용한다.
- 접수·시험·발표를 색상만으로 구분하지 않고 텍스트와 형태를 함께 사용한다.
- 밝은 보라, 마젠타, 네온색, 여러 개의 강한 원색이 경쟁하는 조합은 피한다.
- 시험별 색이 필요하다면 큰 면을 칠하지 말고 작은 식별 표시나 연한 배경에 제한한다.

한국어 타이포그래피 원칙:

- Pretendard, SUIT 또는 동급의 현대적인 한국어 산세리프를 사용한다.
- 본문은 14~16px 범위에서 편하게 읽혀야 한다.
- 한글 자간을 과도하게 줄이지 않는다.
- 날짜와 숫자는 tabular numerals를 사용한다.
- 너무 굵은 제목과 지나치게 작은 보조 문구를 피한다.
- 제목, 본문, 기관명, 날짜의 위계를 굵기뿐 아니라 크기와 간격으로 만든다.

구성 원칙:

- 화면 전체를 카드 모음처럼 만들지 않는다.
- 카드 안에 카드를 중첩하지 않는다.
- 목록과 표는 간격, 정렬, 구분선으로 읽히게 한다.
- 그림자는 팝오버, 하단 시트처럼 떠 있는 요소에만 제한한다.
- 그라디언트, 글래스모피즘, 장식용 블러, 대형 일러스트를 사용하지 않는다.
- 내비게이션 텍스트 아래에 밑줄을 사용하지 않는다.
- 활성 메뉴는 굵기, 작은 마커, 배경 또는 위치 변화로 표현한다.
- 의미 없는 통계 카드, 차트, 후기, 강의·교재 광고, AI 챗봇을 만들지 않는다.

## 화면 1 — 홈

목적: 처음 방문한 사용자가 서비스가 무엇인지 이해하고 바로 시험을 찾거나 현재 접수 일정을 확인한다.

필수 내용:

- 짧은 서비스 설명
- 가장 눈에 띄는 시험명·시행기관 통합 검색
- `현재 접수 중`, `곧 접수 시작`, `이번 달 시험`, `상시시험` 빠른 진입
- 현재 접수 가능한 시험 4~6개를 날짜순으로 보여주는 간결한 목록
- 분야별 탐색
- 이번 주 주요 일정 요약
- 공식 데이터 출처와 마지막 갱신일

홈에 큰 월간 캘린더를 넣지 않는다. 캘린더는 독립 화면으로 연결한다.

첫 화면 안에서 검색, 현재 접수 중 진입, 서비스 범위를 모두 이해할 수 있어야 한다.

## 화면 2 — 시험 찾기

목적: 시험명, 분야, 기관, 상태, 일정으로 원하는 시험을 찾는다.

필수 내용:

- 검색창
- 분야, 시행기관, 시험 유형, 현재 상태, 기간 필터
- 활성 필터와 결과 수
- 정렬: 마감 가까운 순, 시험 가까운 순, 시험명 순
- 결과는 카드 묶음보다 스캔하기 쉬운 행 중심 목록

각 결과 행에 다음을 표시한다.

- 상태
- 시험명
- 시행기관
- 가장 가까운 접수 기간
- 가장 가까운 시험일
- `상세 일정`
- `원서접수` 또는 `공식 정보`
- 관심 시험 저장 버튼

관심 저장 버튼은 다른 핵심 행동보다 강조하지 않는다. 저장 후 `관심 시험에 저장됨` 상태가 명확해야 한다.

모바일에서는 필터를 하단 시트로 열고, 결과의 첫 화면에는 시험명·상태·다음 일정·공식 링크가 우선 노출되게 한다.

## 화면 3 — 시험 상세

목적: 한 시험의 현재 상태, 다음 행동, 전체 일정과 공식 출처를 이해한다.

상단에 다음을 배치한다.

- 시험명
- 시행기관과 시험 유형
- 현재 상태
- 다음 접수 또는 시험 일정
- `원서접수`
- `공식 시험정보`
- 관심 시험 저장 또는 해제

가장 중요한 일정 표현은 **일정표**다. 월간 캘린더만으로 전체 일정을 설명하지 않는다.

기본 일정표 열:

- 회차
- 원서접수
- 추가접수
- 시험일 또는 시험기간
- 발표일
- 비고

날짜가 미정이면 빈칸 대신 `미공고` 또는 `공식 사이트 확인`처럼 의미 있는 상태를 표시한다.

상세 화면의 달력은 필요할 때 여는 보조 보기로 제공하거나 일정표 아래에 배치한다. 사용자가 멀리 떨어진 날짜들을 한 번에 비교할 수 있도록 일정표가 먼저 보여야 한다.

출처, 최종 확인일, 데이터가 오래된 상태, 공식 공고 우선 안내를 일정표 가까이에 둔다.

## 화면 4 — 전체 시험 캘린더

목적: 특정 월과 날짜를 기준으로 전체 공개 시험 일정을 탐색한다.

이 화면은 관심 시험 관리 화면이 아니다. 관심 시험 목록이나 관심 시험 비교표를 절대 포함하지 않는다.

필수 기능:

- 이전 달, 다음 달, 오늘 이동
- 분야와 시행기관 필터
- `접수`, `시험`, `발표` 일정 종류 필터
- 월간 보기와 날짜순 목록 보기 전환
- 날짜별 일정 밀도 확인
- 날짜 선택 후 해당 날짜의 전체 일정 확인
- 일정에서 시험 상세 또는 공식 정보로 이동

데스크톱 권장 동작:

- 월간 캘린더와 선택한 날짜의 일정 목록을 함께 볼 수 있다.
- 한 날짜에 정보가 많으면 모든 이름을 억지로 넣지 않고 `외 N건`으로 축약한다.
- 동일 날짜의 겹치는 일정은 질서 있게 쌓고 위험 경고처럼 표현하지 않는다.

모바일 권장 동작:

- 기본은 날짜 스트립 또는 간결한 월 선택과 날짜순 일정 목록이다.
- 좁은 화면에 데스크톱 월간 캘린더를 축소해 욱여넣지 않는다.
- 월간 격자는 선택 가능한 보조 보기로 제공한다.
- 날짜 상세와 필터는 하단 시트를 사용할 수 있다.

캘린더에서 접수, 시험, 발표는 색 외에도 레이블, 선, 채움, 점 또는 테두리 같은 서로 다른 형태로 구분한다.

## 화면 5 — 관심 시험

목적: 사용자가 직접 저장한 시험만 모아 다음 일정과 전체 일정을 비교한다.

이 화면에는 월간 캘린더를 넣지 않는다.

상단에 다음을 보여준다.

- 관심 시험 개수
- 다음 접수 마감이 가까운 시험
- 정렬: 다음 접수 순, 다음 시험 순, 시험명 순
- `시험 추가` 행동

본문은 두 가지 보기로 구성한다.

### 관심 시험 목록

각 시험 행에 다음을 표시한다.

- 시험명과 시행기관
- 현재 상태
- 다음 접수 기간
- 다음 시험일
- 다음 발표일
- 공식 정보
- 관심 해제

### 관심 시험 일정 비교표

여러 시험의 멀리 떨어진 일정을 한 번에 비교할 수 있는 표를 제공한다.

기본 열:

- 시험명
- 회차
- 원서접수
- 시험일 또는 시험기간
- 발표일
- 공식 정보

시험별 일정이 여러 회차라면 같은 시험 아래에 회차 행을 추가한다. 표가 너무 넓어지면 모바일에서는 각 시험의 일정표를 접고 펼칠 수 있는 세로 구조로 변환한다. 모바일 가로 스크롤을 기본 해결책으로 사용하지 않는다.

관심 시험이 없을 때:

```text
아직 저장한 시험이 없어요.
관심 있는 시험을 저장하면 다음 접수와 시험 일정을 한곳에서 비교할 수 있어요.
[시험 찾기]
```

## 현실적인 예시 데이터

디자인에는 아래 시험을 사용하되 화면을 데이터로 과밀하게 채우지 않는다.

- 정보처리기사 · 한국산업인력공단
- 공인중개사 · 한국산업인력공단
- SQL 개발자(SQLD) · 한국데이터산업진흥원
- TOEIC · YBM
- 컴퓨터활용능력 1급 · 대한상공회의소
- KBS한국어능력시험 · KBS

기준일은 2026년 8월 19일로 한다. 날짜와 요일을 정확히 맞춘다.

예시 일정:

```text
정보처리기사
실기 원서접수 2026.09.21 ~ 10.19
실기시험      2026.10.24 ~ 11.13
최종 발표     2026.12.11

SQLD 제63회
원서접수      2026.10.12 ~ 10.16
시험          2026.11.14
발표          2026.12.04

KBS한국어능력시험 제93회
원서접수      2026.09.07 ~ 10.02
추가접수      2026.10.03 ~ 10.11
시험          2026.10.18
발표          2026.10.29
```

상시시험에는 임의의 확정 시험일을 만들지 않는다. 공식 사이트에서 날짜를 확인해야 한다는 상태를 보여준다.

## 핵심 인터랙션

작동하는 프로토타입으로 다음 흐름을 연결한다.

1. 전역 검색 자동완성
2. 검색 결과 필터와 정렬
3. 시험 결과에서 상세 화면 이동
4. 관심 시험 저장과 해제
5. 관심 시험 페이지의 목록·비교표 전환
6. 캘린더 월 이동
7. 캘린더 일정 종류 필터
8. 날짜 선택 후 일정 목록 표시
9. 월간 보기·날짜순 목록 보기 전환
10. 상세 일정표의 회차 펼치기
11. 공식 시험정보와 원서접수 외부 링크 상태
12. 모바일 필터·날짜 상세 하단 시트

## 재사용 컴포넌트와 변수

색상, 글자, 간격, 모서리, 테두리를 Figma Variables와 Styles로 정의한다. 화면마다 임의 값을 만들지 않는다.

다음 요소는 재사용 가능한 컴포넌트와 상태로 만든다.

- Header / MobileHeader
- GlobalSearch / SearchSuggestion
- NavigationItem
- Button / ExternalLinkButton / IconButton
- FilterControl / MobileFilterSheet
- StatusLabel
- FavoriteButton
- ExamResultRow
- ScheduleTable / ScheduleTableRow
- CalendarHeader / CalendarDay / CalendarEvent
- DayAgendaList
- EmptyState / NotAnnouncedState / StaleDataNotice
- SourceInformation
- BottomSheet / Toast

각 컴포넌트에 default, hover, focus, active, disabled, selected 상태를 필요한 범위에서 제공한다.

## 반응형 기준

- 데스크톱: 1440px
- 태블릿: 768px 또는 834px
- 모바일: 390px

390px, 768px, 1024px, 1440px에서 가로 넘침이 없어야 한다. 단순 축소가 아니라 정보 우선순위를 바꾸는 반응형 레이아웃을 설계한다.

모바일에서 반드시 먼저 보여야 하는 것:

- 홈: 검색과 현재 접수 진입
- 시험 결과: 시험명, 상태, 다음 일정, 공식 링크
- 상세: 시험명, 다음 일정, 공식 CTA
- 캘린더: 선택 날짜와 날짜순 일정
- 관심 시험: 다음 접수일과 다음 시험일

## 접근성과 상태

- WCAG 2.2 AA 수준의 대비
- 최소 터치 영역 44×44px
- 모든 입력에 보이는 레이블
- 키보드 포커스 상태
- 색상 이외의 상태 구분
- 아이콘 단독 버튼의 명확한 이름
- 외부 링크 표시
- 200% 확대에서도 핵심 기능 유지
- `prefers-reduced-motion` 고려

다음 상태를 포함한다.

- 검색 결과 없음
- 일정 미공고
- 접수 종료
- 데이터 확인 지연
- 관심 시험 없음
- 캘린더 일정 없음
- 로딩
- 외부 링크 이동 안내

## 문구 원칙

- 짧고 사실적인 한국어를 사용한다.
- 느낌표와 과장된 마케팅 문구를 피한다.
- 버튼은 행동이 드러나는 동사를 사용한다.
- `D-Day`만 크게 강조하지 않는다.
- 내부 운영 용어를 사용자에게 노출하지 않는다.

사용할 수 있는 문구:

- `시험명 또는 시행기관 검색`
- `현재 접수 중`
- `곧 접수 시작`
- `상세 일정`
- `관심 시험에 저장`
- `관심 시험에서 제거`
- `원서접수`
- `공식 시험정보`
- `전체 시험 캘린더`
- `날짜순 일정`
- `일정은 참고용이며 공식 공고가 우선합니다`

- 모든 화면이 같은 디자인 변수와 재사용 컴포넌트를 사용하는가?
- 로그인이나 자격증명서 관리 기능이 MVP에 섞이지 않았는가?
