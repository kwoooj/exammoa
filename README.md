# exammoa — 시험 일정 타임라인

준비하는 시험 여러 개의 원서접수·시험·발표 일정을 하나의 가로 타임라인에 올려, **일정이 겹치는 구간을 찾아주는** 웹사이트.

로그인 없음. 백엔드 없음. 하루 1회 배치로 정적 JSON을 만들어 서빙한다.

---

## 지금 상태 (2026-08-13)

```bash
npm install
cp .env.example .env       # QNET_KEY 를 채운다
npm run collect            # Q-Net API 수집 → build/*.json
npm run dev                # 화면 확인 (predev 가 public/data 로 복사)
```

| | 값 |
|---|---|
| 수집 종목 | **47** (Q-Net API) |
| 타임라인 행 | **7** (시행그룹) |
| 회차 | 102 (접기 전 499) |
| 이벤트 | 521 |

**타임라인의 한 행은 종목이 아니라 시행그룹이다.** 47종목을 수집했더니 서로 다른 일정이 7개뿐이었고 그중 하나에 29종목이 몰려 있었다. 종목별로 행을 그리면 같은 막대가 29줄 반복되고 정보량이 0이 된다.

   ├─ 요구사항-전체.md          요구사항 106건
   ├─ 화면정의-전체.md          화면 6개 상세
   └─ 조사-저장전략.md          정적 JSON vs DB 검증
data/
├─ exams.seed.json            종목 마스터 58개 (사람이 관리)
├─ groups.seed.json           시행그룹 21개 (사람이 관리)
└─ manual-schedules.json      Q-Net 밖 일정 수기 입력
scripts/
├─ collect.mjs                수집·정규화·그룹 접기

`data/*.seed.json` 은 사람이 고치는 파일, `build/` 는 절대 손으로 안 고치는 파일. 이 경계를 지켜야 cron이 사람의 수정을 덮어쓰지 않는다.

## 확정된 결정 (다시 논의하지 않음)

| 항목 | 결정 |
|---|---|
| 화면 형태 | **D-Day 목록 + 월간 달력.** 가로 타임라인은 이후에 추가 (아래 참고) |
| 타임라인 행 | 종목 아님. **시행그룹** |
| 모바일 | 가로 스크롤 금지. 6개월을 화면 폭에 맞춤 |
| 데이터 수집 | 런타임 API 호출 아님. **하루 1회 배치 → 정적 JSON** |
| 일정 저장 | 정적 JSON (3년 누적 brotli 27KB) |
| 종목 URL | 한글 (`/exam/정보처리기사`) |
| 로그인 | 소셜만 (구글·카카오). 이메일 안 받음. **v1에서** |
| 내보내기 | `.ics` 파일 다운로드. **v1에서** |
| 캘린더 구독 | 안 함 (구글 갱신 24~48시간, PC 웹 전용) |
| robots.txt | **준수.** 금지 기관은 수기·CSV·제외로 처리 |

### 뒤집은 결정 2건 (2026-08-13)

근거 없이 뒤집으면 나중에 또 논의되므로 사유를 남긴다.

**① 충돌 3단계 판정 → D-Day 중심** (이슈 #7)
화면에 충돌 117건이 떴고 그중 106건이 "접수 기간이 겹쳐요" 였다. 접수는 겹쳐도 순서대로 하면 되므로 사용자가 할 일이 없다. `MVP.md` 실측 ②가 이미 답을 적어놨는데 코드가 반영하지 않고 있었다 — 시험 이벤트의 98%가 기간 시행이라 기간끼리는 거의 항상 겹치고, 그래서 '겹친다'는 사실 자체가 정보가 되지 못한다.

**② "월간 격자 아님" → 월간 달력 추가** (이슈 #9)
원래 금지 사유는 *"원서접수는 기간이고 시험도 기간인데 격자가 둘을 같은 칸에 뭉갠다"* 였다. 이 사유는 **충돌 판정 모델의 것이다.** D-Day 모델에서는 사용자가 응시일을 지정하므로 격자에 찍을 것이 점 몇 개(지정한 시험일, 접수 마감일)뿐이라 뭉개질 것이 없다. 그리고 원래 결정이 고려하지 않은 목적이 있다 — **사용자는 자기 일정을 월 단위 격자로 기억하므로**, 대조하려면 같은 형태여야 한다.

가로 타임라인은 여전히 유효하다. 6개월 밀집도를 한눈에 보는 용도로 달력과 함께 둔다. Figma 와이어프레임이 돌아온 뒤 붙인다.

## 알아두면 좋은 함정

- **API 응답에 종목 식별자가 없다.** 요청 시 넣은 `jmCd` 로만 귀속 가능 → 종목별 루프가 불가피하다. 이 중복이 그룹 무결성 검사를 공짜로 준다
- **잘못된 `jmCd` 는 오류 없이 엉뚱한 종목을 보여준다.** `9999`=인수통합, `2010`=폐지. 화이트리스트로만 호출한다
- **응답 0건은 오류가 아니다.** `1324`·`1325`·`0492`·`0493`·`0488`·`0483` 은 타기관 시행이라 정상적으로 빈 응답이다
- **필기시험은 기간 시행(CBT)이다.** 정보처리기사 필기가 26일. 시험이 점이 아니라 막대이고, 기간끼리 겹쳐도 응시일을 고르면 피할 수 있어 `blocking` 에서 제외한다 (`isFlexible`, 4일 이상)
- **한 회차에 접수 구간이 2개다.** 정기접수(4일) + 빈자리접수(시험 직전 2일) → `reg` 의 `seq` 1·2
- **과거 연도 조회가 안 된다.** `implYy=2024` 빈 응답. 매 수집 시 원본을 `build/raw/` 에 보존한다
- **컴활은 상시시험**이라 막대로 못 그린다. "접수는 시험일 4일 전까지" 규칙 카드로 처리한다
- **한국 시험표는 셀에 `M.D(요일)` 로 쓰고 연도는 제목에 한 번만 적는다.** 4자리 연도를 요구하는 정규식은 대부분의 표를 놓친다
- **`robots.txt` 404 는 전면 허용이다** (RFC 9309). "판단 불가"로 처리하면 한능검처럼 값어치 있는 대상을 스스로 차단한다
