# exammoa — 시험 일정 정보 허브

여러 기관에 흩어진 시험의 원서접수·시험·발표 일정을 한곳에 모아 **월간 캘린더로 탐색하고 공식 접수처로 내보내는** 웹사이트.

로그인 없음. 백엔드 없음. 하루 1회 배치로 정적 JSON을 만들어 서빙하고, 빌드할 때 페이지를 HTML로 미리 찍는다.

읽는 순서: 이 파일 → [CLAUDE.md](CLAUDE.md)(작업 규칙) → [docs/reference/화면정의-전체.md](docs/reference/화면정의-전체.md)(화면 정본).

## 지금 상태 (2026-08-14)

```bash
npm install
cp .env.example .env       # QNET_KEY 를 채운다
npm run collect            # 수집 → data/published/*.json
npm run dev                # 화면 확인 (predev 가 public/data 로 복사)
npm run build              # 빌드 + 68개 페이지 사전 렌더
npm run check              # PR 전 검사 한 방
```

| | 값 |
|---|---|
| 노출 종목 | **62** |
| 시행그룹 | **19** (일정이 있는 것) |
| 회차 | 191 (접기 전 499) |
| 이벤트 | 817 |
| 사전 렌더 페이지 | 68 (정적 6 + 종목 62) |

**일정의 주체는 종목이 아니라 시행그룹이다.** 47종목을 수집했더니 서로 다른 일정이 7개뿐이었고 그중 하나에 29종목이 몰려 있었다. 종목별로 막대를 그리면 같은 막대가 29줄 반복되고 정보량이 0이 된다. 캘린더는 그룹 단위로 접고, 접힌 종목은 막대의 속성으로 남겨 상세 패널이 전부 보여준다.

## 화면

화면정의는 [docs/reference/화면정의-전체.md](docs/reference/화면정의-전체.md) 가 정본이다.

| 라우트 | 화면 | 하는 일 |
|---|---|---|
| `/` | S-01 홈 | 검색, 상태 바로가기, 지금 접수 중, 이번 달 미리보기 |
| `/exams` | S-02 탐색 | 검색·필터·정렬, 캘린더에 담기 |
| `/exam/{slug}` | S-03 상세 | 회차별 월간 캘린더, 출처, 공식 링크 |
| `/calendar` | S-04 통합 캘린더 | 전체 일정 모드 · 1~6개 선택 비교 |
| `/about` `/privacy` `/404` | S-05~07 | 출처·개인정보·복귀 |

`/exam/{slug}` 이 검색엔진 유입의 첫 화면이라 62개를 전부 사전 렌더한다. 순수 CSR 이면 크롤러가 받는 HTML 이 빈 `<div id="root">` 하나다.

종목 64개의 수집 경로. 근거와 배제 이유는 [docs/데이터-수집-활용.md](docs/데이터-수집-활용.md).

| 경로 | 종목 | 상태 |
|---|---|---|
| Q-Net API `15074408` | 47 | ✅ 수집 중 |
| 크롤링 (한능검·토익·토스·KBS한국어·리눅스마스터·전산세무회계) | 7 | 구현 완료 |
| 공공데이터 CSV `15062838` (빅분기·SQLD·ADsP) | 3 | 연 1회 수기 반영 |
| 규칙 카드 (컴활·워드·오픽·ITQ) | 5 | 상시시험이라 막대 없음 |
| v0 제외 (정보보안기사) | 1 | robots 금지 + 대체 경로 없음 |
| 보류 (전산회계운용사2급) | 1 | 경로 미정 |

`dataq.or.kr` · `cq.or.kr` · `opic.or.kr` 은 `robots.txt` 가 `Disallow: /` 라 **자동 수집하지 않는다.** 대한상의 `/kor/` 도 금지 경로다.

**링크 삽입은 robots.txt 와 무관하다.** robots 는 자동 크롤러 규약이라 사용자가 클릭해 이동하는 것을 규율하지 않는다. 수집이 금지된 기관도 `agencyUrl` 로 링크한다.

## 확정된 결정 (다시 논의하지 않음)

| 항목 | 결정 |
|---|---|
| 화면 형태 | **월간 캘린더 중심 정보 허브.** 가로 타임라인은 폐기 |
| 일정의 주체 | 종목 아님. **시행그룹** |
| 렌더링 | 빌드 시 사전 렌더 + 하이드레이션. 서버 없음 |
| 색의 뜻 | **색 = 어느 시험 · 모양 = 일정 종류.** 겹치면 색맹·흑백에서 구분이 사라진다 |
| 모바일 | 가로 스크롤 금지. 월간 격자는 7열 유지 |
| 데이터 수집 | 런타임 API 호출 아님. **하루 1회 배치 → 정적 JSON** |
| 종목 URL | 한글 (`/exam/정보처리기사`). NFC 정규화 |
| 겹침 판정 | **하지 않는다.** 기간을 나란히 보여주고 사용자가 판단한다 |
| 개인 계획 | P2. 공식 일정과 시각·문구·저장 위치를 분리 |
| robots.txt | **준수.** 금지 기관은 수기·CSV·제외로 처리 |

### 뒤집은 결정 3건

근거 없이 뒤집으면 나중에 또 논의되므로 사유를 남긴다.

**① 충돌 3단계 판정 → D-Day 중심** (이슈 #7, 2026-08-13)
화면에 충돌 117건이 떴고 그중 106건이 "접수 기간이 겹쳐요" 였다. 접수는 겹쳐도 순서대로 하면 되므로 사용자가 할 일이 없다. 시험 이벤트의 98%가 기간 시행이라 기간끼리는 거의 항상 겹치고, 그래서 '겹친다'는 사실 자체가 정보가 되지 못한다.

**② "월간 격자 아님" → 월간 달력 추가** (이슈 #9, 2026-08-13)
원래 금지 사유는 *"원서접수는 기간이고 시험도 기간인데 격자가 둘을 같은 칸에 뭉갠다"* 였다. 그 뭉갬은 **주 단위 그리드 + 레인 배정**으로 풀린다 — 기간 막대가 주 경계를 넘어 이어지고, 겹치면 다른 줄에 앉는다.

**③ 개인 D-Day 관리 → 공개 정보 허브** (2026-08-14, 화면정의 v1.1.0)
서비스가 파는 것이 "내 시험 관리" 라면 사용자는 먼저 시험을 고르고 응시일을 정해야 한다. 그 앞단이 진입 장벽이고, 정작 사람들이 검색으로 들어와 알고 싶은 것은 **"지금 접수할 수 있는가, 언제인가, 어디서 접수하는가"** 셋이다. 선택 없이도 전체 일정을 보여주고 공식 기관 연결을 종착점으로 삼는다. 가로 타임라인과 개인 D-Day 대시보드를 폐기하고, 가정 날짜·예약일은 P2 의 선택적 로컬 레이어로 내렸다.

## 알아두면 좋은 함정

- **API 응답에 종목 식별자가 없다.** 요청 시 넣은 `jmCd` 로만 귀속 가능 → 종목별 루프가 불가피하다. 이 중복이 그룹 무결성 검사를 공짜로 준다
- **잘못된 `jmCd` 는 오류 없이 엉뚱한 종목을 보여준다.** `9999`=인수통합, `2010`=폐지. 화이트리스트로만 호출하고, 링크를 조립할 때도 같은 화이트리스트를 쓴다
- **응답 0건은 오류가 아니다.** `1324`·`1325`·`0492`·`0493`·`0488`·`0483` 은 타기관 시행이라 정상적으로 빈 응답이다
- **거절은 빈 응답과 응답 구조가 다르다.** 일 1,000회 한도를 넘기면 `OpenAPI_ServiceResponse.cmmMsgHeader` 로 오는데, 이걸 0건으로 읽어 29종목이 조용히 사라진 적이 있다 (#18). 1회 수집 = 47회 호출이라 하루 21회가 상한
- **필기시험은 기간 시행(CBT)이다.** 정보처리기사 필기가 26일. 시험이 점이 아니라 막대다
- **한 회차에 접수 구간이 2개다.** 정기접수 + 빈자리접수 → `reg` 의 `seq` 1·2. 화면에서 둘을 점선으로 갈라야 남은 기회를 놓치지 않는다
- **과거 연도 조회가 안 된다.** `implYy=2024` 빈 응답. 매 수집 시 원본을 `build/raw/` 에 보존한다
- **컴활은 상시시험**이라 막대로 못 그린다. 규칙 카드로 처리하고 접수 마감은 계산하지 않는다
- **한국 시험표는 셀에 `M.D(요일)` 로 쓰고 연도는 제목에 한 번만 적는다.** 4자리 연도를 요구하는 정규식은 대부분의 표를 놓친다
- **`robots.txt` 404 는 전면 허용이다** (RFC 9309). "판단 불가"로 처리하면 한능검처럼 값어치 있는 대상을 스스로 차단한다
- **`<button>` 은 내용을 세로 가운데로 민다.** 달력 날짜 칸을 버튼으로 만들었더니 날짜 숫자가 칸 한가운데 — 정확히 첫 레인 자리 — 에 앉아 막대에 덮였다

## 배포와 운영

**Cloudflare Pages.** 정적 파일만 올린다.

| 설정 | 값 |
|---|---|
| 저장소 연결 | Git 연동. 프로덕션 브랜치 `mvp` |
| 빌드 명령 | `npm run build` |
| 출력 디렉터리 | `dist` |
| 환경변수 (**Production 만**) | `SITE_ORIGIN` = `https://exammoa.pages.dev` |
| Node 버전 | 설정하지 않는다 — `.nvmrc` 를 읽는다 |

`SITE_ORIGIN` 을 **Preview 환경에는 넣지 않는다.** 넣으면 미리보기 배포가 프로덕션 주소를 canonical 로 주장해서 같은 내용이 두 주소로 색인된다. 비워 두면 `CF_PAGES_URL` 로 떨어져 자기 주소를 쓰고, 프로덕션 브랜치가 아니므로 `robots.txt` 가 `Disallow: /` 로 나간다.

호스트에 필요한 동작은 둘인데 Cloudflare Pages 는 **기본으로 둘 다 한다.**

1. **디렉터리 index 서빙** — `/exams` 요청에 `/exams/index.html` 을 준다
2. **없는 경로는 `404.html` 로 (HTTP 404 와 함께)** — 루트로 되돌리는 SPA 폴백을 쓰면 없는 시험 주소가 홈을 200 으로 돌려주고 검색엔진이 그것을 색인한다. `_redirects` 에 `/* /index.html 200` 을 **넣지 말 것.**

### 배포 주소는 빌드 산출물에 박힌다

`SITE_ORIGIN` 이 canonical · `og:url` · JSON-LD · sitemap 67건 · `robots.txt` 의 절대 주소를 만든다. 실측으로 **71개 파일 351군데**다.

없으면 `https://exammoa.example` 로 떨어지는데, **배포 맥락(`CI` 또는 `CF_PAGES`)에서는 빌드가 종료코드 1 로 선다** (`scripts/lib/prerender-html.mjs` 의 `resolveOrigin`). 예전에는 조용히 폴백해서 존재하지 않는 도메인이 정본으로 색인될 수 있었다 — 빌드는 성공하고 자기 검사도 통과하는데 산출물만 틀린 형태였다.

로컬에서 실제 주소로 확인하려면:

```bash
SITE_ORIGIN=https://exammoa.pages.dev npm run build
grep -ro "exammoa.example" dist | wc -l    # 0 이어야 한다
```

`.github/workflows/ci.yml` 도 같은 값을 넣어 빌드한다. CI 는 배포하지 않지만, 진짜 주소로 빌드해야 **자리표시자 유출 검사가 실제로 돈다** — 자리표시자로 빌드하면 그 검사는 스스로를 건너뛴다.

**커스텀 도메인으로 옮길 때**: Cloudflare 에서 도메인을 붙이고 `SITE_ORIGIN` 을 새 주소로 바꿔 재배포한다. **`ci.yml` 의 값도 함께 옮긴다** — 주소가 적힌 곳은 이 둘뿐이다. `pages.dev` 주소는 살려 둔다 — 새 canonical 이 옛 주소에서도 새 주소를 가리키므로 검색엔진이 스스로 옮겨 간다. 정적 호스트라 301 을 낼 수 없어서 이것이 유일한 이전 경로다.

`public/_headers` 가 캐시를 나눈다. 해시 붙은 자산은 영원히, HTML 과 `/data/*.json` 은 캐시하지 않는다 — 일정 데이터가 캐시에 갇히면 화면이 어제 일정을 "최종 확인 오늘" 이라고 말한다.

> GitHub Pages 를 쓰지 않은 이유: 저장소가 비공개라 무료 플랜에서 Pages 가 안 켜지고, 프로젝트 사이트는 `/exammoa/` 하위 경로라 절대 경로를 전부 고쳐야 한다.

⚠️ `schedule` 과 `workflow_dispatch` 는 **기본 브랜치의 파일만 발동한다.** 기본 브랜치는 `mvp` 다 — `.github/workflows/collect.yml` 이 거기 올라가야 하루 1회 배치가 돌고 수동 실행 버튼도 생긴다.

이 문장이 한때 `main` 이라고 적혀 있었고, 그 사이 배치가 **고쳐 놓은 시각으로 돈 적이 없었다.** 새벽 실패를 겪고 cron 을 04:10 → 07:10 KST 로 옮겼는데(#24) 그 커밋이 `mvp` 로만 갔다. 기본 브랜치였던 `main` 의 파일이 계속 발동해서 04:10 이 유지됐고, 실제로 04:52 KST 런이 실패했다. **워크플로 파일은 기본 브랜치에 반영돼야 효력이 생긴다** — 브랜치에서 고치고 초록불을 봤다고 적용된 것이 아니다.

**연 1회 사람이 해야 하는 일**: 2027-01-22 이후 공공데이터포털 `15062838` 에서 새 CSV 를 내려받아 `data/dataq-2027.csv` 로 커밋하고 `collect.mjs` 의 `FILE_SOURCES` 를 갱신한다. 하지 않으면 400일 뒤부터 화면이 경고한다.
