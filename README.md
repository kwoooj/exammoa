# 시험 일정 타임라인

준비하는 시험 여러 개의 원서접수·시험·발표 일정을 하나의 가로 타임라인에 올려, **일정이 겹치는 구간을 찾아주는** 웹사이트.

---

## 지금 만들 것 (v0)

**한 화면. 로그인 없음. 백엔드 없음.**

```
종목 고르기 → 타임라인 보기
```

| | v0에 넣음 | v0에서 뺌 |
|---|---|---|
| 데이터 | Q-Net API 20종목 | 나머지 38종목, 크롤링 |
| 화면 | 홈(선택) + 타임라인 | 종목 상세 페이지, 소개, 처리방침 |
| 기능 | 충돌 표시, URL 공유 | 로그인, 저장, `.ics`, 공식링크 |
| 인프라 | 정적 사이트 + 하루 1회 배치 | DB, Workers |

**v0의 목표는 "타임라인이 실제로 유용한가"를 내 눈으로 확인하는 것.** 그것만 되면 나머지는 나중에 붙인다.

## 확정된 결정 (다시 논의하지 않음)

| 항목 | 결정 |
|---|---|
| 화면 형태 | 월간 격자 아님. **가로 타임라인** (접수=막대, 시험=점) |
| 모바일 | 가로 스크롤 금지. 6개월을 화면 폭에 맞춤 |
| 데이터 수집 | 런타임 API 호출 아님. **하루 1회 배치 → 정적 JSON** |
| 일정 저장 | 정적 JSON (3년 누적 brotli 27KB) |
| 종목 URL | 한글 (`/exam/정보처리기사`) |
| 로그인 | 소셜만 (구글·카카오). 이메일 안 받음. **v1에서** |
| 내보내기 | `.ics` 파일 다운로드. **v1에서** |
| 캘린더 구독 | 안 함 (구글 갱신 24~48시간, PC 웹 전용) |

## 지금 필요한 것 하나

**공공데이터포털에서 Q-Net API 키 발급** (`15074408` 국가자격 시험일정, 자동승인)

키가 있으면 아래 4개가 한 번에 확인된다. 이게 v0의 첫 작업.

1. 응답 날짜 필드의 실제 형식 (미정일 때 `""` 인지 `"00000000"` 인지)
2. 컴활(`0492`)·빅데이터분석기사(`1324`)·정보보안기사(`1325`)가 응답을 주는지
3. 종목당 연간 실제 회차 수
4. 과거 연도(`implYy=2024`) 조회 가능 여부

---

## 알아두면 좋은 함정 3개

- **API 응답에 종목 식별자가 없다.** 요청할 때 넣은 `jmCd`로만 귀속 가능 → 종목별 루프 불가피
- **잘못된 `jmCd`는 오류 없이 엉뚱한 종목을 보여준다.** `9999`=인수통합종목, `2010`=폐지 종목. 화이트리스트 검증 필요
- **필기시험은 기간 시행(CBT)이다.** 정보처리기사 2026 3회 필기가 `08/07~09/01` 26일. 시험일이 점이 아니라 막대이고, 기간끼리 겹쳐도 응시일을 고르면 피할 수 있으므로 `blocking` 판정에서 제외한다 (`isFlexible`, 4일 이상)
- **한 회차에 접수 구간이 2개다.** 정기접수(4일) + 빈자리접수(시험 직전 2일). `seq` 1·2로 구분
- **과거 연도 조회가 안 된다.** `implYy=2024` 빈 응답. 매 수집 시 원본을 `build/raw/` 에 보존
- **컴활은 상시시험**이라 막대로 못 그린다. "접수는 시험일 4일 전까지" 규칙 카드로 처리
