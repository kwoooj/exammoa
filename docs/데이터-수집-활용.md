### 각 경로가 그 경로인 이유 (실측)

**Q-Net API 47종목** — jmCd 보유 53개를 전량 호출한 결과 47개가 정상 응답했다. 지금 20개만 들어오는 건 API 문제가 아니라 `pickExams()` 의 필터 문제다. 응답 0건인 6개(`1324` 빅분기, `1325` 정보보안기사, `0492`·`0493` 컴활, `0488` 워드프로세서, `0483` 전산회계운용사2급)는 전부 타기관 시행이며, `tier: 'X'` 와 `rolling: true` 로 이미 걸러지므로 **별도 블랙리스트가 필요 없다.**

**크롤링 7종목** — 대상 사이트 전부 초기 HTML에 2026 일정표가 들어 있고 robots.txt가 허용한다. 진단 스크립트가 처음에 3곳을 "JS 필요"로 오판했는데, 원인은 사이트가 아니라 `analyze()` 의 정규식이 4자리 연도를 요구한 것이었다 (한국 시험표는 셀에 `M.D(요일)`, 연도는 제목에 한 번).

**CSV 3종목** — dataq.or.kr 은 일정표가 완전한 SSR이지만 `robots.txt` 가 `Disallow: /` 다. 공공데이터포털 파일데이터 `15062838` 에 동일 정보가 있다(`접수시작일`·`접수마감일`·`시험일`·`합격자발표일` 포함, 947행, 로그인 불필요). **갱신주기가 연간·차기등록예정일 2027-01-22** 이므로 매일 배치에 넣을 이유가 없다. 연 1회 수동 다운로드가 비례적이다.

**규칙 카드 5종목** — 확정 회차 달력이 존재하지 않는다. 막대를 그리면 거짓 정보가 된다(`데이터-스키마.md` §3). 대한상의는 2026 달력을 `/kor/images/.../img_2026_examschedule01.png` 로만 내는데, 이 경로는 robots.txt `Disallow: /kor/` 이고 FR-DAT-11의 완료조건이 "대한상의 `/kor/` 경로 접근 시도 없음"이다. **PNG/PDF는 요청조차 하지 않는다.**

**정보보안기사 제외** — cq.or.kr 은 `Disallow: /`, 대체 경로가 없다. KCA 오픈API `15125639` 는 게시판(제목·내용·첨부파일, 날짜 필드 없음)이고 파일데이터 `3043850` 은 2021년에 멈췄다. 게시판 제목에서 정규식으로 날짜를 뽑는 방식은 정확도가 우연에 달려 있고 실패가 조용해서 채택하지 않는다.

### 자동 수집하지 않는 3개 도메인

`dataq.or.kr` · `cq.or.kr` · `opic.or.kr` — 셋 다 `User-agent: * / Disallow: /` (각각 robots.txt를 직접 받아 확인). 사람이 열어 보고 옮기는 것은 무관하지만 **배치가 접근하지 않는다.** 이 구분을 필드 이름으로 강제한다: 자동 수집 대상만 `sourceUrl`, 사용자 클릭용 링크는 `agencyUrl`. `sourceUrl` 이 남아 있으면 언젠가 누군가 크롤 대상에 다시 집어넣는다.

## 2. 수집 → 활용 흐름

```

  │
  │  ── 수집 ─────────────────────────────────────────
  ├─ 소스별 어댑터 실행 (실패는 격리, 전체를 멈추지 않음)
  │    qnet(47종목 · 종목당 1회 호출)  crawl×7  csv  manual
  │    · robots 게이트를 통과한 요청만 나감
  │    · 원본 바이트를 archive/ 에 그대로 보존
  │
  │  ── 정규화 ───────────────────────────────────────
  ├─ 날짜 문자열 → ISO. 파싱 실패는 null (추측하지 않음)
  ├─ 10개 날짜 필드 / 표 컬럼 → events[]  (kind × phase)

  ├─ 드리프트 비교 (회차수·이벤트수·파싱실패·헤더일치·커버월수)
  │    통과 → 해당 소스 전량 교체
```

### 왜 한 행이 종목이 아니라 그룹인가 — 실측

수집된 20종목의 **서로 다른 일정은 4개뿐**이다. 16종목(전기기사·정보처리기사·산업안전기사·건축기사·토목기사·직업상담사2급 등)의 연간 일정이 이벤트 단위로 완전히 동일하다. 47종목으로 넓히면 회차가 139 → 약 330건으로 늘지만 **정보량은 6개 내외로 그대로**다. 종목별로 행을 그리면 같은 막대가 16줄 그려진다.

그래서 `pickExams()` 확장과 그룹 접기는 **같은 작업**이다. 확장만 먼저 하면 화면이 나빠진다.

`groupId` 를 일정 내용 해시로 유도하면 안 된다 — 회차가 바뀔 때마다 id가 흔들려 URL 공유와 `ExamPlan.sessionId` 가 깨진다. **정체성은 시드에 선언, 동일성은 수집 시점에 검증**이 원칙이다.

### 신선도와 출처를 데이터에 싣는 방식

| 값 | 뜻 | 화면 |
|---|---|---|
| `verified` | 기관이 기계 판독용으로 발행 (API·CSV) | 배지 없음 |
| `parsed` | HTML에서 추출. 개편되면 조용히 틀릴 수 있다 | 출처 링크 노출 |
| `manual` | 사람이 입력. 갱신 책임이 사람 | "수기 확인 YYYY.MM.DD" |
| `stale` | 이번 실행에서 소스 실패 → 이전 값 재게시 | "최종 확인: N일 전" 경고 |

- `manual` 은 썩는 걸 막아야 한다. 확인일이 90일을 넘으면 `stale` 로 강등하고 `meta.warnings` 에 올린다. **수기 데이터가 조용히 낡는 게 크롤러가 죽는 것보다 위험하다** — 아무도 알림을 받지 않기 때문이다.
- **낡음 판정은 소스별 주기로 한다.** 하나의 임계(3일)로 재면 연 1회 발행되는 CSV 가 붙는 순간 경고가 **영구히** 켜진다 — 219일 된 것이 그 소스의 정상 상태다. 거짓 경고가 상시로 떠 있으면 진짜 경고를 아무도 읽지 않는다. 소스가 `staleAfterDays` 를 선언하고 `freshnessOf()` 가 각자 임계로 잰다.
- **소스가 자기 관측 시각을 선언할 수 있다.** 연 1회 갱신되는 파일을 오늘 읽었다고 `fetchedAt: now` 를 쓰면 화면이 "최종 확인 오늘" 이라고 거짓말한다. 실패한 소스의 `fetchedAt` 을 갱신하지 않는 것과 같은 이유다.
- **`res.text()` 를 쓰지 않는다.** Fetch 명세상 `text()` 는 언제나 UTF-8 로 디코드하고 `Content-Type` 의 charset 을 무시한다. 한국세무사회 페이지는 `charset=euc-kr` 을 헤더로 선언까지 하는데 `res.text()` 로 읽으면 표 헤더가 통째로 깨져 `tableByHeader()` 가 아무것도 못 찾는다. `lib/csv.mjs` 의 `decodeResponse()` 를 거친다.
- D-day와 "N일 전"은 **저장하지 않는다.** 정적 빌드에서 저장 시점과 조회 시점이 다르다. `fetchedAt` 만 저장하고 클라이언트가 계산한다.
- 회차 해시는 페이로드에서 뺀다. 무작위 문자열이라 압축이 안 된다(`조사-저장전략.md` 실측: 빼면 216회차가 1.8KB 감소).

### 실패해도 사라지지 않게 하는 것 — 해결됨 (Step 2)

원래 `.gitignore` 가 `build/` 와 `public/data/` 를 모두 무시했다. GitHub Actions는 매번 깨끗한 체크아웃에서 도므로 **"이전 빌드 결과"를 읽을 방법이 없었다.** 즉 FR-DAT-07(실패한 소스는 이전 결과 유지)이 코드가 아무리 정확해도 CI에서 무동작이었다. 크롤러 하나가 죽으면 그 그룹이 화면에서 그냥 사라진다.

해결: 산출물과 원본 아카이브를 **저장소에 커밋**한다(`data/published/`, `data/archive/`). 새 결정이 아니다 — `조사-저장전략.md` §6·§7이 이미 "원본 응답 아카이브를 저장소에 커밋", "git 히스토리 자체가 이력 저장소"라고 정해 놓았다. 부수 효과로 `git log -p data/published/sessions.json` 이 그대로 일정 변경 이력이 되어 FR-DAT-08도 해결된다.

`.gitignore` 에 "ignore 하지 말 것" 주석을 박아 두었다. 이 두 경로가 무시되는 순간 폴백이 조용히 무동작으로 돌아간다.

`actions/cache` 는 쓰지 않는다. 7일 미접근·10GB 한도로 **조용히 축출**되는데, 축출되는 날이 크롤러가 깨진 날일 수 있다. 보장 장치가 예고 없이 사라지는 설계는 없는 것보다 나쁘다.

### 조용한 오답을 막는 장치

크롤링은 터지지 않고 어긋난다. 사이트가 표를 개편하면 대개 **빈 표**로 나타나므로, 0건을 조용히 게시하는 것이 가장 위험한 실패다.

- **표를 인덱스나 CSS 클래스로 고르지 않는다.** `tables[0]` 이나 `.tabtop` 은 개편 시 다른 표를 조용히 읽는다. **헤더 텍스트로 고른다** (`회차`·`접수기간`·`시험일시`). 그러면 일치하거나 크게 실패하고, 그 실패가 드리프트 지표 `headerMatch:false` 로 즉시 잡힌다 — 값이 이상해지기 전에 헤더가 먼저 바뀐다.
- 기준선은 직전 1회가 아니라 최근 이력의 **중위값**. 직전과 비교하면 직전이 이미 깨져 있었을 때 깨진 값이 정상으로 승격된다.
- ~~소스 1/3 초과가 동시 실패하면 **아무것도 쓰지 않고** 종료한다.~~ **Step 7 에서 이 규칙을 뺐다.** 근거가 틀렸다 — `mergeStale()` 은 실패한 소스의 회차를 **직전 값 그대로** 계승하고 `fetchedAt` 도 마지막 성공 시각을 유지한다. 즉 실패한 실행이 쓰는 것은 "좋은 데이터를 덮는 나쁜 데이터" 가 아니라 **직전 데이터 + 낡았다는 표시**다. 이 커밋을 막으면 위험을 줄이는 게 아니라 화면에서 경고를 지운다. 대신 **커밋을 막아야 하는 경우는 하나로 좁혔다** (아래).
- **그룹이 갈리면(`groupSplitCount > 0`) 커밋하지 않는다.** `foldGroups()` 가 `groupId` 를 `xxx--슬러그` 로 **바꿔서** 내보내므로, 커밋하면 사용자가 저장한 `ExamPlan.sessionId` 와 공유된 `?p=` 링크가 존재하지 않는 회차를 가리킨다. 낡은 데이터와 성질이 다르다 — 사람이 `groups.seed.json` 을 고쳐야 하므로 자동 커밋 대상이 아니다. 판정은 `scripts/ci-gate.mjs`.
- `--replay=YYYY-MM-DD` 로 그날 원본 바이트에 파서를 재실행한다. 드리프트가 터졌을 때 **사이트가 바뀐 건지 내 파서가 바뀐 건지**를 즉시 가른다. 픽스처는 이미 `build/crawl/*.html` 13개가 있다.

## 3. HTML 파서 의존성 — 판단을 정정한다

계획 단계에서 관용 파서(`node-html-parser`) 도입을 권했다. **근거가 틀렸다.** 저장된 13개 스냅샷의 `<tr>` 개폐를 세어 보면:

```
history-exam    19/19  OK        kca-security   112/114  MISMATCH  (badspan 9)
kbs-korean       9/9   OK        kdata-bigdata   26/25   MISMATCH
toeic           12/12  OK        kdata-sqld      26/25   MISMATCH
toeic-speaking  56/56  OK        kdata-adsp      26/25   MISMATCH
```

**깨진 마크업을 가진 대상은 정확히 robots.txt가 금지한 대상들이다.** `<td class="board_l"span>` 9건도 전부 `kca-security` 에만 있다. 크롤 허용 대상은 전부 균형이 맞는다.

그리고 실제로 필요한 기능은 관대함이 아니라 **rowspan 격자 복원**이다. 리눅스마스터 표는 `리눅스마스터`·`2601회` 가 `1차`/`2차` 하위 행을 rowspan으로 관통해서, 복원하지 않으면 2차 행의 열이 통째로 밀린다. cheerio도 이걸 대신 해주지 않는다 — DOM만 주고 병합 해제는 직접 써야 한다. **즉 의존성을 넣어도 코드량이 줄지 않는다.**

→ **무의존성 유지.** `scripts/lib/html.mjs` 에 격자 확장기 + 헤더 기반 표 선택을 직접 쓴다.

**단, 남은 불확실성을 밝힌다.** 리눅스마스터(`/guidecert1.do`)와 전산세무회계(`license.kacta.or.kr/web/home/Default.aspx`)의 **실제 페이지는 아직 스냅샷이 없다** — 저장된 건 meta refresh 셸과 frameset이다. ### ~~Step 3 — 진단 도구 수정~~ ✅ 완료 (2026-08-13, 이슈 #5)

가장 큰 발견은 오탐이 아니었다. **진단 도구가 robots 를 읽기 전에 페이지를 먼저 받고 있었다** — 금지된 기관(cq.or.kr 344KB 포함)의 페이지를 실제로 가져왔다. 준수를 검증하는 도구가 준수를 어기면 도구 자체가 위험이다. 순서를 뒤집고, 금지면 요청하지 않는다.

robots 상태 분류를 RFC 9309 §2.3.1 대로 재구현했다. 4xx(429 제외)는 robots.txt 없음과 동일하게 전면 허용, 429·5xx·요청실패는 보류. Allow/Disallow 최장일치와 `*`·`$` 도 구현했다 — 이전엔 `startsWith` 만 봐서 `Disallow: /` + `Allow: /$`(dataq) 같은 흔한 패턴을 잘못 읽었다.

날짜 탐지에 연도 없는 `M.D(요일)` 를 추가했다. 오탐 3건의 원인이다. `<script>`·`<style>` 을 걷어낸 뒤 세고, 표 안 날짜를 따로 센다 — 푸터 공지 날짜는 일정이 아니다. `verdict()` 의 연도 하드코딩도 제거했다.

대상 목록을 `groups.seed.json` 에서 읽는다. `manual-schedules.json` 에서 읽던 탓에 이미 알려진 잘못된 URL 2건이 진단에 그대로 반영됐다.

**결과: 크롤 후보 6곳 전부 "SSR 가능".** 리눅스마스터(403 때문에 조용히 건너뛰어지고 있었다)와 전산세무회계(frameset 때문에 "JS 필요" 였다)가 정상 판정됐다. cq.or.kr·OPIc 은 금지로 잡혀 요청하지 않는다.

회귀 테스트 29건을 붙였다 (`npm test`). 네트워크를 타지 않고 실제 응답에서 뽑은 문자열을 픽스처로 쓴다. **이 테스트를 쓰다가 403 버그를 찾았다.**

### Step 5 — 어댑터, payoff 순 (각 2~4시간)
1. **한능검** — priority 1, 마크업 정상, 헤더 `구분|원서접수|취소좌석 접수|시험일시|합격자발표` 가 events에 1:1 대응("취소좌석 접수"가 `reg seq:2`). 가장 깔끔하고 값어치 있다
2. **토익** — priority 1. ~~같은 파서로 **토익스피킹이 공짜**(도메인만 교체)~~ **틀렸다.** 실측하니 토익은 `회차|시험일시|성적발표일시|접수기간` 12행, 토스는 `시험일시|성적발표일|접수기간` 56행이다. 토스는 회차 컬럼이 없어 시험일 순서로 회차를 만들고, 같은 시험일이 여러 행에 중복돼(56행 → 45회차) 시험일로 접는다. 토익은 접수기간 한 칸에 정기접수와 특별추가가 함께 있어 라벨로 자른다. 차이 셋을 `parseWith()` 설정으로 흡수했다
3. **KBS한국어** — 접수·추가접수가 별도 컬럼이라 가장 단순
4. **수기·규칙 카드** ✅ 완료 — 상시 5종목(3그룹). **막대를 그리지 않는 것과 고를 수 없는 것은 다르다.** 지금까지 상시 그룹은 회차가 없어 `publishedExams` 에서 통째로 빠졌고 화면에 아예 안 나왔다. 그룹마다 **이벤트 없는 회차 하나**를 만들어 `ExamPlan.sessionId` 가 가리킬 자리를 준다.
   - **사용자가 예약한 날짜를 넣으면 D-Day 가 생긴다.** 확정 회차가 없을 뿐 사용자는 자기 응시일을 안다 — 그 날짜는 **사용자의 사실**이지 우리가 추측한 값이 아니다. 범위 검사도 하지 않는다(기관이 정한 기간이 없다)
   - **접수 마감은 계산하지 않는다.** "접수는 시험일 약 3주 전까지" 를 날짜로 바꾸면 규칙 4 위반이고, 틀린 마감일 하나가 시험 하나를 통째로 날린다. 규칙 원문과 기관 접수 링크를 주고 사용자가 판단하게 둔다
   - 확인일 규칙은 `staleAfterDays: 180` + 그룹별 `ruleCheckedAt` 으로 넣었다. `observedAt` 을 오늘로 쓰면 화면이 "방금 확인했다" 고 거짓말한다
5. **CSV 임포트** ✅ 완료 — 빅분기·SQLD·ADsP 10회차. 예상한 함정(연도 필터, `순번`을 키로 쓰지 않기, 그룹 0행이면 실패)은 다 맞았고 **예상 못 한 것이 셋 더 있었다.**
   - **파일이 EUC-KR 이다.** `utf8` 로 읽으면 헤더가 깨진다. Node 24 내장 `TextDecoder('euc-kr')` 로 해결 — 인코딩 라이브러리 불필요
   - **`시험장소` 칸에 콤마가 있다.** `split(',')` 로 쪼개면 컬럼이 밀려 `시험유형` 에 `' 4층"'` 같은 값이 조용히 들어온다. RFC 4180 파서가 필요하다
   - **시험명 표기가 연도에 따라 바뀐다.** `SQLD(국가공인 SQL 개발자)` → `SQL 개발자(SQLD)`, `국가기술 빅데이터분석기사` → `빅데이터분석기사-필기`/`-실기`. 매핑에 없는 이름은 조용히 버리지 않고 실패로 집계한다
   - **빅분기는 필기·실기가 별도 행이고 회차 번호가 같다.** 한 `Session` 으로 합치고 `phase` 를 나눈다 (Q-Net 정처기와 같은 모델). 두 회차로 갈리면 타임라인에 같은 종목이 두 줄 나온다
6. **리눅스마스터** ✅ 완료 — ~~연도를 어디서 가져올지부터 정해야 한다~~ **막힌 문제가 아니었다.** `'2026'` 이 페이지에 없는 것은 맞지만 **회차 표기가 연도를 담고 있다**: `2601회` 의 앞 두 자리가 26 이다. 추측이 아니라 표 안의 값이므로 규칙 4 를 어기지 않는다. 수집 연도와 다르면 버린다 (작년 표가 남아 있을 수 있다). 함정 둘: **1급·2급이 한 표에 섞여 있고 일정이 다르다**(등급으로 거른다), **1차·2차가 별도 행이고 회차 번호가 같다**(한 회차로 합친다)
7. **전산세무회계** ✅ 완료 — 표 16개 중 헤더로 고르는 것이 실제로 필요했다. 예상 못 한 것 셋: **페이지가 EUC-KR 이다**(아래), 구분자가 `~` 가 아니라 **`∼`(U+223C)**, **표에 회차 칸이 없다**. 회차 번호는 공지 배너에만 있고 표와 묶여 있지 않은데, 그 배너는 해당 기간에만 뜬다 — 배너로 번호를 매기면 배너가 사라지는 날 `sessionId` 가 흔들려 저장된 계획이 깨진다. 연내 순번을 `seq` 로 쓰고 라벨은 시험일로 붙였다(`08.01 시행`)

기관 경계를 넘는 1~3번이 붙는 시점에 **비로소 실제 충돌 판정이 검증 가능해진다**(`MVP.md` 실측 ③).

2. **`collect.yml` 을 `main` 에 올린다.** `schedule` 과 `workflow_dispatch` 는 기본 브랜치의 파일만 발동한다 — `mvp` 에만 있으면 cron 도, 수동 실행 버튼도 없다.

### v1로 미루는 것
- 정보보안기사 (robots 금지 + 대체 경로 없음. 재조사 시작점은 이 문서 §1)
- 일정 변경 알림 (FR-DAT-08 정교화 — 알림 없이는 용처가 없다)
- 같은 일정을 두 출처로 교차 검증
- 표 선택 실패 시 자동 후보 제안 같은 자기치유 — **조용한 오답의 원천이다.** 사람이 고치게 둔다

## 명시적으로 배제한 방법

| 방법 | 배제 이유 |
|---|---|
| 대한상의 PNG OCR / PDF 파싱 | robots `/kor/` 금지(FR-DAT-11 완료조건). OCR이 `1.26` 을 `126` 으로 읽어도 파이프라인은 통과한다. 상시시험에 확정일을 붙이는 것 자체가 스키마 §3 위반 |
| dataq·cq·opic 헤드리스 브라우저 | `Disallow: /`. 덧붙여 Playwright ~300MB는 "월 0원·무의존" 제약과 충돌 |
| KCA 게시판 API 제목에서 정규식으로 날짜 추출 | 정확도가 우연에 달려 있고 실패가 조용하다 |
| 크롤러 1개 실패로 전체 빌드 실패 | FR-DAT-06 위반. 사이트가 낡은 채 멈추고 사용자는 그 사실을 모른다 |
| `groupId` 를 내용 해시로 유도 | 매일 id가 흔들려 URL 공유(FR-STA-01·02)와 `ExamPlan.sessionId` 가 깨진다 |
| 파싱 결과를 `exams.seed.json`·`manual-schedules.json` 에 자동 커밋 | 사람이 고치는 파일과 기계가 쓰는 파일의 경계 붕괴(스키마 §1). cron이 사람의 수정을 덮는다 |
| `ExamEvent` 에 시각 저장 | `conflicts.ts` 가 날짜·ISO주 단위. `overlaps()` 의미가 흔들린다 |
| D-day·`staleDays` 를 빌드 시 계산해 저장 | 정적 빌드에서 저장 시점 ≠ 조회 시점 |
| `actions/cache` 로 이전 빌드 복원 | 조용히 축출된다. 축출되는 날이 크롤러가 깨진 날일 수 있다 |
