# 시험 상세정보 수집·승인 운영

시험 일정은 하루 단위로 바뀌지만 시험 구성·합격 기준은 천천히 바뀐다. 반대로 잘못된
문항 수, 시간, 배점은 사용자의 준비 계획을 직접 망친다. 따라서 상세정보는 일정 배치와
분리하고 **자동 게시하지 않는다.**

## 데이터 경계

| 경로 | 작성 주체 | 의미 | 공개 여부 |
|---|---|---|---|
| `data/detail-sources.seed.json` | 사람 | 공식 출처·수집 방식·주기 | 아니오 |
| `data/archive/details/` | 수집기 | 원문 바이트와 내용 해시 | 아니오 |
| `data/proposals/details/` | 수집기 | 미승인 정규화 후보 | 아니오 |
| `data/exam-details.seed.json` | 승인자 | 검토 완료 정본 | 예 |
| `public/data/details.json` | publish | 정본의 배포 사본 | 예 |

후보 파일은 `sourceId`, UTC 관측시각, SHA-256 승인 데이터 해시(`contentHash`),
원문 해시(`archiveHash`), 원문 경로, 전수 집계와
상세정보 배열을 가진다. `missing`·`unclassified`·`failures` 중 하나라도 있으면 승격할
수 없다. 승격이 끝난 후보는 `status: approved`와 승인 시각을 남겨 같은 원문에 대한
Draft PR이 매주 반복되지 않게 한다.

## 출처 상태

- `active`: 구현된 adapter와 허용된 robots 판정이 있어 주간 수집 대상이다.
- `planned`: 공식 출처는 등록했지만 parser가 아직 없어 자동 수집하지 않는다.
- `blocked`: robots 금지나 기술적 차단 때문에 자동 요청하지 않는다. 공식 문서를 사람이
  내려받아 승인형 업로드로만 넣는다.

`manual-upload`는 검증을 생략한다는 뜻이 아니다. 공식 문서에서 정규화한 JSON을 동일한
후보·전수 집계·해시 승인 과정으로 넣는 방식이다.

한 승인형 출처가 종목별 공식 페이지를 여러 개 가질 때는 `sourceUrls`에 전수 URL을
등록한다. 이 필드는 수기 대조용으로만 허용되며 자동 수집 어댑터는 사용할 수 없다.

한 URL이 여러 종목을 담으면 공통 fetch를 쓰고, Q-Net처럼 종목 코드별 요청이 필요한
출처는 adapter의 `collect()`가 원문 묶음과 파서 입력을 함께 반환한다. 원문 해시와 전수
종목 집계는 어느 방식이든 동일하게 적용한다.

## 명령

```bash
npm run details:coverage
npm run details:coverage -- --json

# 활성 자동 출처 전부. planned와 manual-upload는 건너뛴다.
npm run collect:details

# 봇 차단·PDF·수기 대조 출처의 승인형 입력. 정규화 JSON과 공식 원문을 함께 보관한다.
npm run collect:details -- --source=ybm-toeic-format --input=work/toeic-detail.json --evidence=work/toeic-official.html

# 후보 파일의 contentHash를 리뷰에서 확인한 뒤에만 정본으로 승격
npm run details:promote -- --source=ybm-toeic-format --approve=<64자리 SHA-256>

# 전 종목 반영이 끝난 뒤 활성화할 최종 게이트
npm run details:coverage -- --strict
```

승격 명령은 `--approve` 값이 정규화 상세값의 `contentHash`와 정확히 일치하지 않으면
실패한다. 보관 원문도 다시 해시해 `archiveHash`와 다르면 승격하지 않는다.
승격 후 `npm run check`와 브라우저 검증을 거치고, Draft PR에서 두 차례 독립 리뷰한다.

## 출처 우선순위와 보조 출처

상세정보는 다음 순서로 찾는다.

1. 시행기관·접수처·자격 발급기관의 공식 페이지, API, 규정, 공고, PDF
2. 주무부처·공공 자격 등록부·공식 지역 운영기관처럼 책임 주체를 확인할 수 있는 1차 자료
3. 해커스·에듀윌 등 시험 준비 서비스와 최신 수험서의 공개 시험 안내

3단계 자료는 공식 정보가 아니라 **보조 출처**다. 공식 페이지가 접근 불가하거나 시험
구성 일부를 공개하지 않을 때 다음 조건을 모두 만족하는 저변동 구성 필드에만 쓴다.

- 허용: 영역·과목명, 전체/영역 문항 수, 전체/강제 구간 시간, 전체/영역 배점,
  응시 방식처럼 시험 구성에 해당하는 사실
- 금지: 일정·접수기간·시험 시작 시각, 응시료·환불, 응시자격, 공인/민간 분류,
  합격 기준, 점수 유효기간처럼 변경 시 사용자의 의사결정에 직접 손해를 주는 값
- 서로 독립적인 보조 출처 두 곳이 같은 현행 값을 제공해야 한다. 같은 보도자료·교재를
  재게시한 페이지 두 곳은 하나로 센다.
- 출처마다 URL·확인일·적용 시험 버전을 남기고, 후보에는 `보조 출처 교차검증·공식
  미공개`라고 명시한다. 보조 출처만으로 채운 값은 공식 출처 커버리지에 포함하지 않는다.
- 현재 공개 스키마와 화면은 구성 링크를 `공식 시험 구성`으로 표시한다. 출처 등급,
  두 개 이상의 근거 URL, `보조 출처 교차검증` 화면 라벨을 지원하기 전에는 보조 출처
  후보를 정본으로 승격하지 않는다.
- 공식 자료가 나중에 확인되거나 보조 출처와 충돌하면 공식 값을 우선하고 후보를 다시
  검토한다. 두 출처가 일치하지 않으면 값을 만들지 않고 `공식 안내 없음`을 유지한다.
- robots.txt와 이용약관을 지킨다. 문제·해설·교재 본문은 수집하지 않고 공개된 사실,
  URL, 확인일만 증거로 보관한다. 자동 수집이 허용되지 않으면 승인형 수동 입력만 쓴다.

종목별 작업에서는 먼저 공식 출처 공백을 필드 단위로 기록하고, 보조 출처 후보를 두 곳
이상 대조한 뒤 승인 후보를 만든다. 이 절차는 공식 출처 탐색을 생략하는 지름길이 아니다.

## 시간·문항·배점 입력 규칙

1. 실제 시험에서 과목별 시간을 강제하지 않으면 `stage.durationMinutes`에 전체 시간만 둔다.
2. 강제 구간이 있을 때만 `timedBlocks`를 쓰고 합계는 단계 전체 시간과 일치시킨다.
3. 과목별 배점을 공식적으로 제공하지 않으면 `stage.totalScore`에 전체 점수만 둔다.
4. 문항·시간이 적응형 등으로 변하면 `{min,max}` 범위를 쓰며 고정값을 추측하지 않는다.
5. 공식 출처에 없는 값은 만들지 않는다. 전 종목 통일성은 거짓 숫자가 아니라
   `공식 안내 없음`과 미공개 사유로 확보한다.
6. 출제 경향은 공식 시험 구성과 섞지 않고 별도 선택 정보로 관리한다.

## 주간 배치

생긴 경우에만 `bot/detail-refresh-*` 브랜치와 Draft PR을 만들고, `mvp`에는 직접 쓰지
않는다. 확인일만 달라진 변경은 의미 변경으로 세지 않는다.

Draft PR을 병합하는 것으로 운영 데이터가 바뀌지는 않는다. 후보 검토 후 해시를 명시해
정본으로 승격한 별도 커밋이 `mvp`에 병합되어야 Cloudflare 빌드가 반영한다.
