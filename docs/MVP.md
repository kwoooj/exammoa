## 실측으로 뒤집힌 전제 3개 (2026-08-13)

`npm run probe` · `npm run collect` 실측 결과에 따라 v0 설계가 바뀌었다.

**① 일정의 주체는 종목이 아니라 시행그룹이다.**
20종목을 수집했더니 서로 다른 일정이 **4개**뿐이었다. 기사·산업기사·직업상담사·사회조사분석사 등 **16종목의 연간 일정이 픽셀 단위로 동일**하다. 종목별로 행을 만들면 같은 행이 3개 그려지고 정보량이 0이 된다.
→ 타임라인의 한 행 = **시행그룹**. 종목은 그룹에 속한 라벨.
→ 수집도 그룹당 1회로 충분하다.

**② 시험이 거의 전부 기간 시행이라 "같은 날 불가" 충돌이 없다.**
시험 이벤트 243개 중 **239개(98%)가 4일 이상**(필기 중위 5일, 실기 중위 19일). 기간끼리 겹쳐도 응시일을 조정할 수 있다.
→ 사용자가 **응시 예정일을 지정**하면 그 시험이 고정일이 되고, 그때부터 충돌 판정이 의미를 갖는다. 지정이 없으면 판정하지 않는다.
→ 주별 밀집도 바는 **도입하지 않는다**(같은 그룹 종목을 여러 개 골라도 선택 개수의 배수로만 움직여 정보가 없음).

**③ Q-Net만으로는 비교할 대상이 없다.**
기관 경계를 넘을 때만 실제 충돌이 생긴다. 대표 타기관 시험을 v0 필수 범위로 올린다.
→ `data/manual-schedules.json` 에 수기 입력. 크롤러(FR-DAT-10)는 v1 유지.

**이름 표기 주의**: "빅데이터분석기사"·"정보보안기사"는 이름에 '기사'가 붙지만 공단 정기 일정과 무관하다. 그룹·종목 표시에 **시행기관을 반드시 함께** 노출한다.

**정규화 규칙**은 `reference/데이터-스키마.md` §4. 핵심만 옮기면:

| Q-Net 필드 | → event |
|---|---|
| `docRegStartDt`/`docRegEndDt` | `{kind:"reg", phase:"written"}` |
| `docExamStartDt`/`docExamEndDt` | `{kind:"exam", phase:"written"}` |
| `docPassDt` | `{kind:"result", phase:"written"}` (start=end) |

- 점 이벤트는 `start === end`
- 날짜 없으면 event 생성 안 함
- `qualgbCd`가 `C`/`W`면 `phase:"single"`

## 3단계 — 충돌 탐지 (반나절)

서로 **다른 종목** 간에만 판정. 지난 날짜 제외.

| 단계 | 조건 | 색 |
|---|---|---|
| `blocking` | 두 `exam` 이벤트가 **날짜** 겹침 | 빨강 |
| `warning` | 한쪽 `exam`과 다른쪽 `reg` 종료일이 **같은 주(월~일)** | 주황 |
| `info` | `reg` 구간끼리 겹침 | 회색 (기본 접힘) |

- [ ] 충돌 구간 배경 음영
- [ ] 요약 문장 1줄 ("10월 11일 주 — A 시험일과 B 실기 접수가 겹칩니다")
- [ ] 충돌 없으면 "겹치지 않아요"
- [ ] 단계 높은 순 → 날짜 이른 순 정렬

`warning`만 주 단위인 게 의도된 비대칭. 시험 전주에 다른 시험 접수 마감이 있으면 잊어버린다는 게 이 서비스가 잡으려는 지점이다. ISO 주는 **월요일 시작** (시험이 주말이라 일요일 시작이면 "전주" 계산이 틀어짐).
