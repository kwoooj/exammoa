# 요구사항 정의서

문서 버전 0.1.0 · 2026-08-13 · 대상 범위: MVP

---

## 0. 문서 사용법

| 표기 | 의미 |
|---|---|
| **ID** | `FR-{영역}-{번호}` 기능 요구사항 / `NFR-{영역}-{번호}` 비기능 요구사항 |
| **우선순위** | `M` 필수(없으면 출시 불가) · `S` 중요(있어야 제품답다) · `C` 선택(여유되면) · `W` 이번엔 안 함 |
| **수용기준** | 이 조건을 만족하면 해당 요구사항이 완료된 것으로 본다 |

우선순위 `M`만 구현해도 서비스는 동작해야 한다. `M`이 전체의 절반을 넘으면 범위 설정이 잘못된 것이므로 재검토한다.

## 1. 기능 요구사항 — 종목 선택 (SEL)

|---|---|---|---|

| FR-SEL-02 | 종목명 및 약칭(`short`)으로 검색할 수 있다 | M | "정처기" 입력 시 정보처리기사가 검색됨 |
| FR-SEL-03 | 종목을 복수 선택·해제할 수 있다 | M | 선택 시 즉시 반영, 재클릭으로 해제 |
| FR-SEL-04 | 동시 선택 개수는 최대 8개로 제한한다 | S | 9번째 선택 시도 시 "최대 8개까지 선택할 수 있어요" 안내, 기존 선택은 유지 |
| FR-SEL-05 | 선택된 종목 수를 항상 표시한다 | M | 헤더 또는 하단 고정 영역에 "3개 선택" 형태로 노출 |
| FR-SEL-06 | 선택 0개일 때 타임라인으로 진행할 수 없다 | M | 진행 버튼이 비활성 상태이거나, 누르면 안내 표시 |
| FR-SEL-07 | 카테고리별 종목은 `priority` 오름차순으로 정렬한다 | S | 같은 카테고리 내에서 priority 1이 먼저 표시됨 |
| FR-SEL-08 | 큐레이션 목록에 없는 종목을 사용자가 요청할 수 있다 | C | 텍스트 입력 + 전송. 수집 대상 후보로 기록 |

## 3. 기능 요구사항 — 충돌 탐지 (CFL)

이 서비스의 핵심 계산이다. 판정 규칙을 코드보다 문서에서 먼저 고정한다.

| ID | 요구사항 | 우선 | 수용기준 |
|---|---|---|---|
**2026-08-13 — FR-CFL-01~07 을 폐기하고 FR-DDAY-01~07 로 교체했다.**

실측에서 시험 이벤트의 98%가 기간 시행이라 기간끼리는 거의 항상 겹치고, 화면에 뜬 충돌 117건 중 106건이 "접수 기간이 겹쳐요" 였다. 접수는 겹쳐도 순서대로 하면 되므로 사용자가 할 일이 없다. 즉 '겹친다' 는 사실 자체가 정보가 되지 못했다. 근거는 `../데이터-수집-활용.md`.

폐기 사유를 남기는 이유는, 근거 없이 지워두면 나중에 누가 "충돌 판정이 없네" 하고 다시 만들기 때문이다.

| ID | 요구사항 | 등급 | 완료 조건 |
|---|---|---|---|
| FR-DDAY-01 | 종목·회차를 고르면 그 회차의 모든 단계에 계획을 만든다 | M | 응시일을 정하기 전에도 원서접수 마감 D-Day 가 보임 |
| FR-DDAY-02 | 기간 시행 시험은 기간 안에서 응시일을 지정한다 | M | 지정 전에는 "기간 중 응시일을 정하면 D-Day가 생겨요" |
| FR-DDAY-03 | 지정한 시험일과 원서접수 마감일의 D-Day 를 가까운 순으로 보여준다 | M | 지난 항목 제외, 오늘은 `D-DAY` 로 표기 |
| FR-DDAY-04 | 이미 지정한 시험일과 같은 날을 고르면 알려준다 | M | "이미 2026.10.11에는 OOO이 있습니다". **막지는 않는다** |
| FR-DDAY-05 | 빈자리접수를 마감으로 쓰지 않는다 | M | 정기접수(seq 1) 마감을 쓴다 |
| FR-DDAY-06 | 기간을 벗어난 지정은 응시일로 인정하지 않는다 | M | D-Day 를 만들지 않고 다시 고르게 함 |
| FR-DDAY-07 | 상시시험·미공고 회차는 지정 대상이 아니다 | M | 규칙 카드만 노출 |

폐기된 요구사항 (참고용):

| ID | 원래 요구사항 |
|---|---|
| ~~FR-CFL-01~~ | 선택된 서로 다른 종목 간 이벤트 충돌을 판정한다 |
| ~~FR-CFL-02~~ | 충돌을 3단계로 분류한다 |
| ~~FR-CFL-03~~ | 충돌 구간을 타임라인 배경에 음영으로 표시한다 |
| ~~FR-CFL-04~~ | 충돌 요약을 문장으로 제공한다 |
| ~~FR-CFL-05~~ | 충돌이 없으면 그 사실을 명시한다 |
| ~~FR-CFL-06~~ | 지난 날짜의 충돌은 판정 대상에서 제외한다 |
| ~~FR-CFL-07~~ | 상시시험은 충돌 판정 대상이 아니다 (FR-DDAY-07 로 승계) |

### 충돌 판정 규칙

| 단계 | 조건 | 표시 | 문구 예시 |
|---|---|---|---|
| **blocking** | 서로 다른 종목의 `kind = exam` 이벤트가 **하루라도 날짜가 겹침** | 빨강 | "같은 날 두 시험을 볼 수 없어요" |
| **warning** | 한 종목의 `kind = exam` 이벤트와 다른 종목의 `kind = reg` 이벤트 **종료일**이 같은 ISO 주(월~일)에 속함 | 주황 | "시험 준비 주에 다른 시험 접수 마감이 있어요" |
| **info** | 서로 다른 종목의 `kind = reg` 구간이 겹침 | 회색 | "접수 기간이 겹쳐요. 순서만 확인하세요" |

**설계 의도**

- `blocking`은 **물리적으로 불가능**한 상태다. 날짜 단위로 판정한다.
- `warning`은 **주 단위**로 판정한다. 시험 전주에 다른 시험 접수 마감이 있으면 잊어버리기 쉽다는 것이 이 서비스가 잡으려는 실패 지점이다. 날짜 단위로 보면 이 케이스를 놓친다.
- `info`는 실질적 문제가 아니므로 경고로 표시하지 않는다. 경고를 남발하면 사용자가 전부 무시한다.
- ISO 주 기준은 **월요일 시작**이다. 시험이 대부분 주말에 치러지므로 일요일 시작으로 잡으면 "시험 전주"가 잘못 계산된다.

## 4. 기능 요구사항 — 상태 유지·공유 (STA)

| ID | 요구사항 | 우선 | 수용기준 |
|---|---|---|---|

| FR-STA-02 | URL을 직접 입력·붙여넣기 하면 해당 선택 상태가 복원된다 | M | 다른 브라우저에서 같은 URL 접속 시 동일 타임라인 |
| FR-STA-03 | Q-Net 종목코드가 없는 종목(T3·T4)은 접두 표기로 URL에 담는다 | M | `?exams=1320,t3:토익` 형태로 동작 |
| FR-STA-04 | 마지막 선택을 `localStorage`에 저장한다 | S | 쿼리스트링 없이 재방문 시 이전 선택 복원 |
| FR-STA-05 | URL 복원 시 존재하지 않는 코드는 무시하고 나머지를 렌더한다 | M | 잘못된 코드가 섞여도 오류 화면 없이 유효한 종목만 표시 |
| FR-STA-06 | 현재 타임라인 URL을 복사할 수 있다 | S | 복사 버튼 클릭 시 클립보드에 URL, 완료 피드백 표시 |
| FR-STA-07 | 브라우저 뒤로가기가 선택 이력을 따라간다 | C | 히스토리 이동 시 선택 상태가 함께 되돌아감 |
| FR-STA-08 | 로그인·회원가입 기능을 제공하지 않는다 | M | 인증 관련 UI가 어디에도 없음 |

**FR-STA-01·02 근거**: 무회원 전략에서 URL이 사실상 계정 역할을 한다. 동시에 카카오톡 공유가 그대로 되므로 **바이럴 채널이 된다.** 이 두 요구사항은 편의 기능이 아니라 성장 전략의 구현체다.

## 6. 기능 요구사항 — 공식사이트 연결 (LNK)

| ID | 요구사항 | 우선 | 수용기준 |
|---|---|---|---|
| FR-LNK-01 | 모든 종목에 공식 정보 페이지 링크를 제공한다 | M | 58종목 전부 링크 존재. 새 창으로 열림 |
| FR-LNK-02 | `jmCd`가 있는 종목은 Q-Net 딥링크를 패턴으로 자동 생성한다 | M | `crf005.do?id=crf00505&gSite=Q&jmCd={code}` 형태. 53종목 자동 생성 |
| FR-LNK-03 | `jmCd`를 화이트리스트로 검증하고, 미검증 코드는 링크를 생성하지 않는다 | M | 검증 실패 시 Q-Net 종목 목록 페이지로 폴백 |
| FR-LNK-04 | 시행기관이 공단이 아닌 종목은 기관 자체 페이지 링크를 함께 제공한다 | S | 컴활→대한상의, 빅분기→dataq, 정보보안기사→cq.or.kr |
| FR-LNK-05 | 원서접수 경로를 별도 링크로 제공한다 | S | 비로그인 접근 가능한 접수 안내 페이지로 연결 |

**FR-LNK-02·03 근거**: Q-Net 종목 상세 페이지는 타 기관 시행 종목(컴활·빅데이터분석기사·정보보안기사)까지 포함하므로 **`jmCd` 하나로 53종목 전부를 단일 패턴으로 커버**할 수 있다. 다만 잘못된 `jmCd`는 HTTP 오류나 리다이렉트 없이 **엉뚱한 종목을 정상 응답으로 표시**한다(`9999`=인수통합종목, `0000`=한자실력급수, `2010`=폐지 종목, 미지정=백지). 사용자를 잘못된 시험 정보로 보내는 것은 마감을 놓치게 만드는 것과 같은 종류의 피해이므로 화이트리스트 검증이 필수다.

| FR-EXP-03 | 구간 이벤트는 종일 일정, 시점 이벤트는 단일 종일 일정으로 변환한다 | M | 원서접수 3일 → 3일짜리 종일 일정 |

**설계 의도**: 캘린더 **구독(ICS URL)** 방식은 채택하지 않는다. 구글 캘린더는 구독 갱신이 24~48시간이고 PC 웹에서만 추가할 수 있으며 개별 이벤트를 삭제할 수 없다. **파일 다운로드 방식은 담긴 일정을 사용자가 소유**하므로 자유롭게 수정·삭제할 수 있고, 인증·심사·비용이 전혀 없다.

### 로그인 방식 결정 근거

| 방식 | 판정 | 사유 |
|---|---|---|
| **구글** | **채택** | `openid`·`email`·`profile`만 쓰면 **OAuth 검증 불필요**, 미검증 앱 100명 캡도 적용되지 않음(캡은 sensitive·restricted 스코프 전용). 즉시 사용 가능 |
| **카카오** | **채택** | 회원번호·닉네임·프로필사진은 **기본 제공**이라 심사가 없고 사용자 수 제한도 없다. 리다이렉트 URI 등록만으로 즉시 사용 |
| 네이버 | Phase 2 | **사전 검수 필수**(영업일 2~4일). 검수 전에는 테스터 20명까지만 로그인 가능 |
| 자체 이메일 + 비밀번호 | 제외 | 아래 참조 |
| 이메일 매직링크 | 제외 | 메일함을 열어야 하는 마찰 |

**자체 이메일·비밀번호를 제외하는 이유**는 "단순하다"는 직관과 반대로 구현·법적 부담이 가장 크기 때문이다.

- 개인정보보호법 시행령 제30조 및 안전성 확보조치 기준 고시 제7조①에 따라 **비밀번호는 일방향 암호화 저장이 법적 의무**다. 양방향 암호화 저장은 위법이며 3천만원 이하 과태료 대상이다
- 비밀번호 재설정 흐름에 **이메일 발송이 불가피**하다. 즉 매직링크를 피해도 결국 메일함을 열어야 하는 지점이 생긴다
- 메일 발송을 위해 도메인 확보 또는 무료 트랜잭셔널 메일 서비스 연동이 필요하다
- Cloudflare Workers 무료 티어의 **요청당 CPU 10ms** 안에서 bcrypt·Argon2를 돌리기 어렵다. 소셜 로그인 전용이면 이 문제가 발생하지 않는다

**FR-ACC-03 근거**: 이 서비스가 저장하는 것은 "어떤 시험을 준비하는가"뿐이고, 알림 기능이 없는 MVP에서는 이메일이 필요하지 않다. 이메일을 받지 않으면 카카오 비즈 앱 전환도 불필요해지고, 개인정보보호법 제16조의 최소수집 원칙을 자연스럽게 충족한다. **필요 없는 정보를 받지 않는 것이 가장 값싼 보안 대책이다.**

**FR-ACC-07 근거**: 개인정보보호법 제22조의2는 만 14세 미만 아동의 개인정보 처리에 법정대리인 동의와 그 확인을 요구한다. 확인 수단(법정대리인 문자·카드정보·본인인증)은 개인 개발자가 구축하기 어려우므로, 만 14세 미만은 가입을 차단하는 것이 현실적인 준수 방법이다.

| NFR-PRIV-06 | 전송 구간을 암호화한다 | M | 전 경로 HTTPS |
| NFR-PRIV-07 | 선택 동의 항목을 두지 않는다 | S | 필수 항목만 받으므로 선택 동의가 존재하지 않음 |

**NFR-PRIV-04 근거**: 개인정보보호법 제16조 제3항은 필요 최소한을 넘는 정보의 수집에 동의하지 않는다는 이유로 서비스 제공을 거부할 수 없도록 한다. 로그인이 기능 이용의 조건이 되면 동의 자체가 무효로 판단될 수 있다.

**NFR-PRIV-05 근거**: 개인정보보호법 제21조는 목적 달성 시 지체 없는 파기를, 표준 개인정보 보호지침 제10조는 정당한 사유가 없으면 5일 이내 파기를 요구한다. 시행령 제16조는 전자적 파일의 경우 복원 불가능한 방법으로 영구 삭제할 것을 정한다. `deleted_at` 플래그만 세우는 방식은 파기가 아니다. 카카오 회원번호·구글 sub 값도 개인정보이므로 삭제 대상이다.

## 12. 이번 범위에서 제외 (W)

명시적으로 하지 않기로 결정한 것들이다. 나중에 "왜 안 했지"를 다시 논의하지 않기 위해 기록한다.

| 항목 | 사유 |
|---|---|
| 알림 발송(카카오·이메일·푸시) | MVP는 수요 검증 단계. 알림톡은 개인사업자 등록이 전제 |
| 이메일 수집 | 알림이 없는 MVP에서 이메일이 필요한 용도가 없음. 받지 않으면 카카오 비즈 앱 전환도 불필요 |
| 자체 이메일·비밀번호 회원가입 | 비밀번호 일방향 암호화 법적 의무, 재설정 흐름의 메일 발송 불가피, Workers CPU 10ms 제약. 소셜 로그인보다 부담이 큼 |
| 이메일 매직링크 로그인 | 메일함을 열어야 하는 마찰 |
| 네이버 로그인 | 사전 검수 영업일 2~4일. 검수 전 테스터 20명 제한 |
| 캘린더 구독(ICS URL·Google Calendar API) | 구글 캘린더 구독은 갱신 24~48시간, PC 웹 전용, 개별 삭제 불가. `.ics` 파일 다운로드로 대체 |
| 이미지·PDF 내보내기 | `.ics`로 목적 달성. print 스타일은 여력 시 |
| 청년 정책·지원금 | 신청기간 데이터가 비정형. Phase 3 |
| 모바일 앱 | Play 신규 개인 계정 테스터 12명 × 14일 요건 |
| 시험 정보(합격률·교재·후기) | 범위 확산 |
| 학습 계획·진도 관리 | 일정 조회 서비스의 범위를 넘음 |
| 결제·유료 기능 | 유료 전환 시 사업자등록 + 통신판매업 신고 필요 |
| 만 14세 미만 가입 | 법정대리인 동의 확인 수단을 개인 개발자가 구축하기 어려움 |

## 13. 확정된 결정
