# 데이터 스키마 — 시험 일정 타임라인 MVP

버전 0.1.0 · 2026-08-13

## 설계 원칙

**하나만 기억하면 됨: 시험 종류별 특수성을 상위 스키마에 넣지 않는다.**

"필기 접수 / 필기 시험 / 필기 발표 / 실기 접수 / 실기 시험 / 실기 발표"를 각각 고정 필드로 두면 아래 네 케이스에서 전부 깨진다.

| 케이스 | 왜 깨지나 |
|---|---|
| 과정평가형·일학습병행 (`qualgbCd` = C, W) | 필기·실기가 하나의 시행계획으로 통합됨 |
| 국가전문자격 (`qualgbCd` = S) | 실기(작업형) 개념이 없어 필드가 공백 |
| TOEIC | 정기접수 + 추가접수 = 같은 성격의 접수 구간이 2개 |
| 컴활·워드·OPIc | 상시시행. 확정 날짜가 아니라 규칙("시험일 4일 전까지")만 존재 |

그래서 **모든 날짜를 `events[]` 하나로 정규화**한다. 타임라인 렌더러는 `kind`가 구간인지 점인지만 보면 되고, 새로운 시험 유형이 들어와도 스키마를 안 건드린다.

## 1. 파일 구조

```
data/
├─ exams.seed.json        수기 큐레이션 (종목 마스터, 손으로 관리)
├─ groups.seed.json       시행그룹 마스터 (손으로 관리)
├─ fees.seed.json         응시료 기준값·공식 재검증 경로 (138종목)
├─ detail-sources.seed.json 상세정보 공식 출처·수집 상태
├─ exam-details.seed.json 승인된 시험 한눈에·시험 구성
├─ manual-schedules.json  Q-Net 밖 일정 수기 입력
└─ published/             수집 산출물 (기계가 쓴다. 하루 1회 배치가 커밋한다)
   ├─ exams.json          seed + 수집 결과 병합 + 공식 링크 조립 규칙
   ├─ groups.json         시행그룹 + 이번 수집의 회차 수
   ├─ sessions.json       회차별 일정 전량 (groupId 기준)
   ├─ meta.json           수집 시각, 그룹 수, 소스별 성공/실패
   ├─ provenance.json     회차별 해시·관측 시각 (화면에 내보내지 않는다)
   └─ history.json        드리프트 기준선용 이력
```

`*.seed.json`·`manual-schedules.json`은 사람이 고치는 파일, `data/published/`는 절대 손으로 안 고치는 파일 (`build/` 는 진단·스크래치 전용이고 git ignore 대상이다). 이 경계를 지켜야 cron이 사람의 수정을 덮어쓰지 않는다.

`publish.mjs`는 정상 수집 기준본 위에 최신 종목·그룹·응시료 시드를 결합한다. 아직 일정
수집기가 없는 공개 시험은 날짜를 만들지 않고 `catalog-placeholders`의 `tbd` 회차만
붙인다. 따라서 기관 장애로 일정 수집이 실패해도 승인된 카탈로그 변경은 배포할 수 있고,
실패한 수집 산출물을 저장소에 커밋할 필요가 없다.

**일정의 주체는 종목이 아니라 시행그룹이다.** `Session`은 `examSlug`가 아니라 `groupId`를 갖는다. 실측(2026-08-13): 47종목을 수집했더니 서로 다른 일정이 **7개**뿐이었고 그중 하나에 29종목이 몰려 있었다. 종목별로 회차를 만들면 499건이 되는데 접으면 102건이다.

`groupId`는 `groups.seed.json`에 **선언**하고, 수집기가 그룹 내 종목들의 이벤트 지문이 실제로 같은지 **검증**한다. 갈리면 조용히 하나를 고르지 않고 변종별로 쪼갠 뒤 `meta.groupSplits`에 기록하고 종료코드 1을 낸다. 지문을 그룹 id로 쓰지 않는 이유: 회차가 바뀔 때마다 id가 흔들려 URL 공유와 `ExamPlan.sessionId`가 깨진다.

## 2. Exam (종목 마스터)

```jsonc
{
  "slug": "정보처리기사",        // URL 경로. 한글 그대로 (SEO 유입에 유리)
  "name": "정보처리기사",
  "short": "정처기",             // 검색 alias. null 허용
  "jmCd": "1320",                // Q-Net 종목코드 4자리. null이면 Q-Net 밖
  "qualgbCd": "T",               // T 국가기술 / C 과정평가형 / W 일학습병행 / S 국가전문
  "series": "기사",
  "category": "it",
  "tier": "T1",                  // 수집 경로 등급 (아래 표)
  "priority": 1,                 // 1~4. 큐레이션 목록 정렬용
  "fee": {                       // published/exams.json에만 병합
    "items": [{ "label": "필기", "amount": 19400 }],
    "checkedAt": "2026-08-19"
  },
  "agency": null,                // 시행기관이 공단이 아닐 때만 채움
  "sourceUrl": null,             // 크롤링 대상 URL
  "collect": "api",              // api | crawl | manual
  "rolling": false,              // true면 타임라인에 막대 안 그림
  "rollingRule": null,           // "상시시험. 접수는 시험일 4일 전까지"
  "multiReg": false              // true면 같은 kind의 event가 2개 이상 올 수 있음
}
```

응시료의 정본은 `exams.seed.json`이 아니라 `fees.seed.json`이다. Q-Net 47종목은
공식 상세페이지의 수수료 표를 매일 파싱해 인상분을 자동 반영한다. robots.txt가 허용된
타 기관 공식 페이지는 현재 금액 fingerprint를 확인하고, 자동 접근이 금지됐거나 안정적인
기계 판독 경로가 없는 소스는 90일 재확인 기한을 둔다. 실패 시 직전 금액을 유지한 채
`meta.feeFailures`와 CI 빨간불로 알린다.

**tier**

| tier | 의미 | 개수 |
|---|---|---|
| T1 | Q-Net 시험일정 API 직결. 즉시 수집 | 47 |
| T3 | Q-Net 밖. 개별 크롤링·CSV·수집 연결 대기 | 83 |
| T4 | 상시시행. 규칙 카드로만 처리 | 8 |
| X | 일정 수집 경로 미확보. 화면 비노출 | 2 |

합계 140종목이며 `X` 2종목을 제외한 138종목을 노출한다. `rolling: true`인 상시시험은
events가 빈 규칙 카드로, 수집 연결 대기 시험은 `scheduleState: import-pending`인 `tbd`
회차로 나온다. tier(수집 경로)와 mode(일정 성격)는 독립 축이다.

## 3. Session (회차) + Event (날짜)

```jsonc
{
  "id": "1320-2026-3",           // {jmCd}-{implYy}-{implSeq}
  "examSlug": "정보처리기사",
  "year": 2026,
  "seq": 3,                      // 시행회차. 상시면 null
  "label": "2026년 정기 기사 3회",  // Q-Net description 원문
  "mode": "scheduled",           // scheduled | rolling
  "status": "confirmed",         // confirmed | tbd  (cancelled 는 쓰지 않는다)
  "events": [
    {
      "kind": "reg",             // reg 접수 | exam 시험 | result 발표
      "phase": "written",        // written 필기 | practical 실기 | single 통합
      "start": "2026-08-04",
      "end": "2026-08-07",
      "seq": 1,                  // 같은 kind가 여럿일 때 (정기=1, 추가=2)
      "label": "필기 원서접수",
      "note": null,
      "timing": {                // 공식 시각이 있을 때만. 추정값 금지
        "start": "10:00",       // HH:mm, Asia/Seoul
        "end": "18:00",
        "timezone": "Asia/Seoul",
        "status": "confirmed"  // confirmed | varies | select-on-booking
      }
    },
    { "kind": "exam",   "phase": "written",   "start": "2026-08-23", "end": "2026-08-23", "seq": 1, "label": "필기시험" },
    { "kind": "result", "phase": "written",   "start": "2026-09-10", "end": "2026-09-10", "seq": 1, "label": "필기 합격발표" },
    { "kind": "reg",    "phase": "practical", "start": "2026-09-22", "end": "2026-09-25", "seq": 1, "label": "실기 원서접수" },
    { "kind": "exam",   "phase": "practical", "start": "2026-11-01", "end": "2026-11-16", "seq": 1, "label": "실기시험" },
    { "kind": "result", "phase": "practical", "start": "2026-12-12", "end": "2026-12-12", "seq": 1, "label": "최종 합격발표" }
  ],
  "source": {
    "provider": "qnet",
    "endpoint": "getQualExamSchdList",
    "fetchedAt": "2026-08-13T04:00:00Z",
    "hash": "sha256:…"           // 변경 감지용. 알림 붙일 때 필요
  }
}
```

### 규칙

- **점 이벤트는 `start === end`.** 렌더러가 분기하지 않게 하려는 의도. `start === end`면 점, 다르면 막대.
- **미정은 `start: null` + `status: "tbd"`.** 빈 문자열이나 `"미정"` 같은 문자열을 넣지 말 것. 날짜 파싱이 조용히 실패한다.
- **`mode: "rolling"`이면 `events`는 빈 배열.** 대신 exam의 `rollingRule`을 카드로 노출. 상시시험을 억지로 막대로 그리면 거짓 정보가 된다.
- **`seq`는 `kind` 안에서의 순번.** TOEIC 추가접수는 `{kind:"reg", seq:2, note:"추가접수"}`.
- **D-day는 저장하지 않는다.** 정적 빌드라 저장 시점과 조회 시점이 다르다. 클라이언트에서 계산.
- **시각은 공식 소스가 명시할 때만 `timing`에 저장한다.** 날짜만 있는 일정에 `00:00`을 만들지 않는다.
- **회차·시험장별로 시각이 다르면 단일 시각을 저장하지 않는다.** `status: "varies"` 또는 `"select-on-booking"`과 안내 문구를 사용한다.
- **시험 시작과 입실 마감은 다른 값이다.** 입실 마감은 `admissionDeadline`으로 분리한다.

## 4. Q-Net API 매핑

`GET https://apis.data.go.kr/B490007/qualExamSchd/getQualExamSchdList`

| 응답 필드 | → event |
|---|---|
| `docRegStartDt` / `docRegEndDt` | `{kind:"reg", phase:"written"}` + 공통 접수시간 10:00~18:00 |
| `docExamStartDt` / `docExamEndDt` | `{kind:"exam", phase:"written"}` + `timing.status:"varies"` |
| `docPassDt` | `{kind:"result", phase:"written"}` (start=end, 발표 09:00) |
| `pracRegStartDt` / `pracRegEndDt` | `{kind:"reg", phase:"practical"}` + 공통 접수시간 10:00~18:00 |
| `pracExamStartDt` / `pracExamEndDt` | `{kind:"exam", phase:"practical"}` + `timing.status:"varies"` |
| `pracPassDt` | `{kind:"result", phase:"practical"}` (start=end, 발표 09:00) |
| `implYy` / `implSeq` / `description` | session의 `year` / `seq` / `label` |

`qualgbCd`가 `C`(과정평가형) 또는 `W`(일학습병행)이면 필기/실기가 통합 시행계획이므로 **`phase`를 `"single"`로 정규화**한다. `S`(국가전문)는 `prac*` 필드가 공백이므로 해당 event를 생성하지 않는다.

Q-Net 일정 API 자체는 날짜만 제공한다. 접수 10:00~18:00과 발표 09:00은 Q-Net 종목별 공식 일정의 공통 안내를 함께 적용한다. 실제 시험 시각은 접수한 시험장·일자와 수험표에서 정해지므로 단일 시각을 만들지 않고 `status:"varies"`로 저장한다.

### ⚠️ 함정: 응답에 종목 식별자가 없다

`getQualExamSchdList` 응답에는 **`jmCd`도 종목명도 없다.** 즉 종목을 알아내려면 요청 시 `jmCd`를 넣고 그 응답을 해당 종목에 귀속시키는 수밖에 없다.

→ **종목별 루프가 불가피하다.** `jmCd`를 가진 53종목(T1 47 + T2 6) × 1회 = 53 호출/일. 개발계정 한도가 1,000건/일이니 여유 있음.

```
for exam in exams where exam.jmCd != null:
    GET getQualExamSchdList?implYy=2026&jmCd={exam.jmCd}&dataFormat=json
    → 응답 회차들을 exam.slug에 귀속
```

### 인증·한도

| | |
|---|---|
| 인증 | data.go.kr `serviceKey` |
| 한도 | 개발계정 1,000건/일. 운영계정은 활용사례 등록 시 증액 |
| 승인 | 개발 자동승인 / 운영 심의승인 |

**종목코드 전량 확보**: `15003024` (`http://openapi.q-net.or.kr/api/service/rest/InquiryListNationalQualifcationSVC/getList`)는 파라미터가 `serviceKey` 하나뿐이라 1회 호출로 전 종목을 준다. 응답 필드는 `jmcd` / `jmfldnm` / `qualgbcd` / `seriescd` — **소문자**다. 시험일정 API 파라미터는 `jmCd`(대문자 C)이므로 혼동 주의.

## 5. 수집 파이프라인

```
GitHub Actions (하루 1회, 04:00 KST)
  │
  ├─ 1. exams.seed.json 로드
  ├─ 2. T1/T2 → Q-Net API 종목별 루프 (jmCd 있는 것만)
  ├─ 3. T3 → 크롤러 (TOEIC, KBS한국어, 한능검)
  ├─ 4. 정규화 → sessions.json
  ├─ 5. 전 회차 hash 비교 → 변경분 로그
  └─ 6. 정적 빌드 + 배포
```

**실시간 API 호출은 하지 않는다.** 시험 일정은 연초에 확정되고 거의 변하지 않으므로 하루 1회 배치로 충분하다. 결과적으로 DB도 서버도 필요 없다.

**부분 실패를 허용해야 한다.** 크롤러 하나가 죽었을 때 전체 빌드를 실패시키면 사이트가 낡은 채로 멈춘다. 소스별로 성공/실패를 `meta.json`에 기록하고, 실패한 소스는 **이전 빌드 결과를 유지**한 채 UI에 "최종 확인: N일 전" 을 표시한다.

## 6. URL 설계

정본은 [화면정의-전체.md §1](화면정의-전체.md) 이다. 여기서는 데이터와 닿는 부분만 적는다.

| 경로 | 용도 |
|---|---|
| `/` | 홈. 검색과 이번 달 미리보기 |
| `/exams?q=&category=&status=&date=&sort=` | 탐색. 필터 상태가 전부 주소에 남는다 |
| `/exam/정보처리기사` | 종목 단독 페이지 (사전 렌더, SEO 진입점) |
| `/calendar?exams=정보처리기사,SQLD&month=2026-10` | 통합 캘린더. **slug 콤마 구분, 최대 6개** |

선택을 **jmCd 가 아니라 slug 로** 넘긴다. jmCd 는 11종목에 없고(Q-Net 밖), 있는 것도 사람이 읽을 수 없어 공유된 링크가 무엇인지 알 수 없다. slug 는 URL 이 곧 시험 이름이다.

개인 가정 날짜·예약일은 공유 URL 에 넣지 않는다 (화면정의 §8.2). 브라우저 로컬에만 둔다.

## 7. 검증 케이스

스키마를 고칠 때마다 아래 6개를 통과시킬 것.

| # | 케이스 | 기대 |
|---|---|---|
| 1 | 정보처리기사 (T, 필기+실기) | event 6개, phase written/practical |
| 2 | 국가전문자격 (S, 실기 없음) | event 3개, practical event 미생성 |
| 3 | 과정평가형 (C, 통합) | phase 전부 `single` |
| 4 | TOEIC (접수 2세트) | 같은 회차에 `{kind:"reg", seq:1}` + `{kind:"reg", seq:2}` |
| 5 | 컴활 (상시) | `mode:"rolling"`, events 빈 배열, rollingRule 노출 |
| 6 | 차년도 미공고 | `status:"tbd"`, start null. 렌더러가 크래시 없이 "일정 미정" 표시 |

케이스 5와 6이 실제로 가장 많이 터진다. 상시시험을 막대로 그리려는 시도와 `null` 날짜에 `new Date()`를 먹이는 것.
