## 0. 이 문서 읽는 법

작업 단위는 `W{단계}-{번호}` 다. 각 작업에는 **대응 요구사항 ID**, **산출 파일**, **완료 조건**이 붙어 있다. 완료 조건을 만족하지 못하면 다음 작업으로 넘어가지 않는다.

- 요구사항 106건 중 **v0 대상은 58건**. 나머지 48건은 §6에 제외 사유와 함께 전량 기재했다. 빠진 것이 아니라 미룬 것이다
- 작업 항목은 71개다
- 이미 끝난 작업은 §1 표에 `완료`로 표시했다
- `probe` 결과에 따라 분기하는 작업은 §7에 정리했다

**진행 순서 원칙**: 데이터 계약을 먼저 고정하고(W1~W2), 목업으로 화면을 다 만든 뒤(W3~W6) 실데이터를 붙인다. API 응답 확인을 기다리며 UI가 멈추지 않게 하려는 것이다.

## 2. W1 — API 진단 및 수집 스크립트 확정

- **작업**: `npm install` → `QNET_KEY` 설정 → `npm run probe`
- **완료 조건**: 진단 출력 5개 항목이 모두 채워진다
- **산출물**: 없음 (출력 기록)

### W1-2 파서를 실제 응답에 맞춤

- **대응**: FR-DAT-02, FR-DAT-03
- **작업**: `extractItems()`가 레코드를 찾지 못했다면 실제 응답 구조에 맞게 수정. 필드명이 문서와 다르면 `normalize()`의 필드 참조도 함께 수정
- **파일**: `scripts/collect.mjs`
- **완료 조건**: `jmCd=1320`으로 회차 1건 이상 파싱

### W1-3 미정 날짜 판정 보정

- **대응**: FR-TML-10, FR-DAT-05
- **작업**: 진단 [2]에서 확인된 빈 값 표현을 `isBlank()`에 반영. 현재는 `null`·빈 문자열·`0`만 처리
- **파일**: `scripts/collect.mjs`
- **완료 조건**: 빈 날짜가 event를 생성하지 않고, 전 필드가 비면 `status: "tbd"`

### W1-4 T2 종목 등급 재조정

- **대응**: FR-DAT-02
- **작업**: 진단 [4] 결과에 따라 `data/exams.seed.json`의 `tier` 수정
  - 응답 있음 → `T2` → `T1`로 승격

- **파일**: `data/exams.seed.json`
- **완료 조건**: `tier` 값이 실측과 일치

### W1-5 20종목 확정 및 수집

- **대응**: FR-DAT-01, FR-DAT-02
- **작업**: `npm run collect` 실행. `pickExams()` 필터(T1·T2 / 비상시 / priority ≤ 2 / 20개)가 의도대로 뽑는지 확인

- **완료 조건**: `meta.json`의 `failed`가 비어 있거나, 실패 종목이 목록에서 제외됨

## 3. W2 — 데이터 계약 고정·목업

### W2-1 데이터 로딩 경로 정리

- **대응**: NFR-OPS-01
- **작업**: `build/*.json`을 `public/data/`로 복사하는 npm 스크립트 추가. 현재는 수동 복사
- **파일**: `package.json`
- **완료 조건**: `npm run collect` 후 `npm run dev`에서 데이터가 보인다

### W2-2 목업 데이터 생성

- **작업**: 실데이터가 없어도 화면을 개발할 수 있게 목업 생성 스크립트 작성. 아래 6개 경계 케이스를 **반드시 포함**
  1. 필기+실기 정상 (이벤트 6개)
  2. 실기 없음 (이벤트 3개)
  3. 필기·실기 통합 (`phase: "single"`)
  4. 접수 2세트 (`seq: 1`, `seq: 2`)
  5. 상시시험 (`mode: "rolling"`, events 빈 배열)
  6. 일정 미공고 (`status: "tbd"`)
- **추가로 충돌 3단계가 모두 발생하는 조합**을 포함시킨다
- **파일**: `scripts/mock.mjs`, `public/data/*.json`
- **완료 조건**: 목업만으로 W3~W6 개발이 가능하고, 6개 케이스가 화면에서 깨지지 않는다

### W2-3 페이로드 최적화

- **대응**: NFR-PERF-03, NFR-PERF-04
- **작업**: `source` 필드를 클라이언트 페이로드에서 제외하고 별도 파일로 분리
- **파일**: `scripts/collect.mjs`
- **완료 조건**: `sessions.json`이 압축 후 50KB 이하 (실측 근거: 216회차 brotli 9.7KB)
