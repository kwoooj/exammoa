## 1. 정보 구조 (IA)

```
/                                 S-01  종목 선택 (홈)
├─ /timeline?exams={codes}        S-02  타임라인
├─ /exam/{slug}                   S-03  종목 단독 페이지  ← 검색 유입 진입점
├─ /my                            S-06  내 저장 목록 (로그인 필요)
├─ /privacy                       S-04  개인정보 처리방침
└─ /about                         S-05  서비스 소개 · 데이터 출처

모달  로그인 (구글 · 카카오)
모달  탈퇴 확인
```

화면은 6개다. 소셜 로그인만 쓰므로 **회원가입 폼·비밀번호 찾기·이메일 인증 화면이 전부 없다.** 로그인은 별도 페이지 대신 모달로 처리해 진행 중인 선택 상태를 잃지 않게 한다.

**로그인은 선택 기능이다.** S-01·S-02·S-03의 모든 기능은 로그인 없이 동작하고, 로그인이 추가하는 것은 S-06(저장 목록)뿐이다.

### 주요 동선

| 동선 | 경로 | 비중 가정 |
|---|---|---|
| 검색 유입 | 검색 → S-03 → S-02 | 가장 큼. SEO가 유일한 성장 엔진 |
| 직접 방문 | S-01 → S-02 | 재방문자 |
| 공유 링크 | 카카오톡 → S-02 (선택 상태 복원) | 바이럴 |

**S-03이 유입 관문이고 S-02가 목적지**다. S-01은 오히려 트래픽이 적을 것으로 가정한다. 따라서 S-03에서 S-02로 넘어가는 전환 설계가 S-01의 완성도보다 중요하다.

## 3. S-01 종목 선택 (홈)

### 3.1 목적

처음 온 사람이 **3초 안에 무엇을 하는 곳인지 알고, 30초 안에 종목 2~3개를 고르게** 한다.

### 3.2 레이아웃

```
┌──────────────────────────────────────────────┐
│  시험정책캘린더                    [3개 선택]  │
├──────────────────────────────────────────────┤
│                                              │
│  준비하는 시험을 고르면                        │
│  일정이 겹치는 구간을 찾아드려요                 │
│                                              │
│  ┌──────────────────────────────────────┐    │
│  │ 시험 이름 검색  (예: 정처기)            │    │
│  └──────────────────────────────────────┘    │
│                                              │
│  IT · 개발                                   │
│  [정보처리기사] [정보처리산업기사] [빅데이터…]   │
│                                              │
│  안전 · 환경 · 품질                            │
│  [산업안전기사] [위험물산업기사] [품질경영기사]   │
│                                              │
│  … (카테고리 7개)                             │
│                                              │
│  찾는 시험이 없나요?  [알려주세요]              │
│                                              │
├──────────────────────────────────────────────┤
│  정보처리기사 · 산업안전기사 · 토익              │
│              [일정 보기 →]                    │
└──────────────────────────────────────────────┘
```

### 3.3 구성 요소

| 요소 | 명세 | 요구사항 |
|---|---|---|
| 헤드라인 | 서비스 가치를 한 문장으로. "모아보기"가 아니라 "겹치는 구간"을 말함 | — |
| 검색 입력 | 종목명 + 약칭(`short`) 부분 일치. 입력 즉시 필터 | FR-SEL-02 |
| 카테고리 섹션 | 7개. `categories` 순서 고정 | FR-SEL-01 |
| 종목 칩 | 칩 형태 토글 버튼. 선택 시 채움 + 체크 아이콘 | FR-SEL-03 |
| 칩 정렬 | 카테고리 내 `priority` 오름차순 | FR-SEL-07 |
| 상시시험 표시 | 컴활·워드·OPIc 칩에 "상시" 보조 라벨 | FR-TML-09 |
| 하단 고정 바 | 선택 종목명 나열 + 진행 버튼 | FR-SEL-05 |
| 종목 요청 | 텍스트 입력 + 전송 | FR-SEL-08 |

### 3.4 상태·예외

| 상태 | 화면 |
|---|---|
| 선택 0개 | 하단 바 비활성. "시험을 1개 이상 골라주세요" | FR-SEL-06 |
| 선택 8개 도달 | 추가 선택 시도 시 "최대 8개까지 선택할 수 있어요". 기존 선택 유지 | FR-SEL-04 |
| 검색 결과 없음 | "'{입력어}' 시험을 찾지 못했어요" + 종목 요청 유도 | |
| `localStorage`에 이전 선택 존재 | 해당 칩이 선택 상태로 복원 | FR-STA-04 |

### 3.5 문구 원칙

칩 라벨은 `short`가 있으면 그것을, 없으면 `name`을 쓴다. 화면 폭이 좁은 모바일에서 "산업위생관리산업기사"처럼 긴 이름이 두 줄로 넘어가면 카테고리 전체가 무너진다.

## 4. S-02 타임라인

### 4.1 목적

**선택한 시험들의 일정 충돌을 한눈에 발견**하게 한다. 이 화면 하나가 서비스의 전부다.

### 4.2 레이아웃

```
┌──────────────────────────────────────────────┐
│  ← 시험 바꾸기          [링크 복사]  [3개 선택] │
├──────────────────────────────────────────────┤
│  ■ 원서접수  ● 시험일  ● 합격발표              │
│                                              │
│         8월   9월   10월  11월  12월  1월      │
│  정처기  ▬─  │  ▬  │ ░░░ │ ▬▬▬ │  ●  │      │
│  산안기      │ ▬ ● │ ░▬░ │ ▬▬  │     │      │
│  토익        │  ●  │ ░●░ │  ●  │  ●  │      │
│         ┃(오늘)          ↑충돌 음영             │
│                                              │
│  ⚠ 10월 11일 주 — 토익 시험일과 산업안전기사    │
│     실기 접수가 겹칩니다                        │
│                                              │
│  ── 다가오는 일정 ─────────────────────       │
│  D-9    정처기  실기 원서접수 시작              │
│  D-31   토익    시험일                        │
│  D-38   산안기  실기 원서접수 마감              │
│                                              │
│  ── 상시시험 ────────────────────────       │
│  컴퓨터활용능력 1급                             │
│  상시시험 · 접수는 시험일 4일 전까지             │
│  [대한상공회의소에서 확인 ↗]                    │
│  ※ 확정 날짜가 없어 캘린더 파일에는 포함되지 않아요 │
│                                              │
│  ── 내보내기 ─────────────────────────       │
│  [캘린더에 담기 (.ics)]  [이 조합 저장하기]      │
└──────────────────────────────────────────────┘
```

### 4.3 구성 요소

| 요소 | 명세 | 요구사항 |
|---|---|---|
| 범례 | 접수(막대) · 시험(점) · 발표(점). 색 + 형태 병행 | FR-TML-03, NFR-A11Y-01 |
| 가로축 | 오늘부터 6개월. 월 경계 세로 실선 | FR-TML-04 |
| 축 이동 | 이전 3개월 / 다음 3개월 | FR-TML-05 |
| 오늘 선 | 전체 높이 관통 수직선 | FR-TML-06 |
| 종목 행 | 선택 순서대로. 라벨은 `short` 우선 | FR-TML-01 |
| 구간 이벤트 | 막대. `start ≠ end` | FR-TML-02 |
| 시점 이벤트 | 점. `start = end` | FR-TML-02 |
| 지난 이벤트 | 불투명도 저하 | FR-TML-07 |
| 이벤트 상세 | 탭·클릭 시 날짜(YYYY.MM.DD) + 라벨 | FR-TML-08 |
| 추가접수 | 정기접수와 다른 패턴 또는 `note` 라벨로 구분 | FR-TML-11 |
| 충돌 음영 | 해당 날짜 범위 세로 밴드. 단계별 색 | FR-CFL-03 |
| 충돌 요약 | 아이콘 + 문장. 단계별 문구 | FR-CFL-04 |
| 다가오는 일정 | D-day 오름차순. 지난 이벤트 제외 | FR-TML-12 |
| 상시시험 섹션 | 타임라인 밖 별도 카드 + 공식 링크. `.ics` 제외 안내 | FR-TML-09, FR-LNK-04, FR-EXP-05 |
| 링크 복사 | 클립보드 복사 + 완료 피드백 | FR-STA-06 |
| 캘린더에 담기 | 선택 종목 전체를 `.ics` 파일로 다운로드 | FR-EXP-01·03·04 |
| 이 조합 저장하기 | 비로그인 시 로그인 모달, 로그인 시 이름 입력 후 저장 | FR-ACC-04 |
| 대체 표 | 시각적으로 숨김. 스크린리더 접근 | NFR-A11Y-02 |

### 4.4 충돌 표시

| 단계 | 음영 | 아이콘 | 문구 패턴 |
|---|---|---|---|
| blocking | 빨강 계열 | 경고 삼각형 | "{날짜} — {A}와 {B} 시험일이 같은 날이에요. 하나를 선택해야 해요" |
| warning | 주황 계열 | 주의 | "{월일} 주 — {A} 시험일과 {B} {이벤트명}이 겹칩니다" |
| info | 회색 | 정보 | "{A}와 {B} 접수 기간이 겹쳐요. 순서만 확인하세요" |

- 여러 충돌이 있으면 **단계 높은 순 → 날짜 이른 순**으로 정렬한다
- `info`는 기본 접힘 상태로 두고 개수만 표시한다. 경고를 남발하면 사용자가 전부 무시한다
- 충돌 0건이면 "선택한 N개 시험은 일정이 겹치지 않아요" 표시 · FR-CFL-05

### 4.5 상태·예외

| 상태 | 화면 | 요구사항 |
|---|---|---|
| 선택 1개 | 충돌 판정 불가. 충돌 영역 대신 "시험을 하나 더 추가하면 겹치는 일정을 확인할 수 있어요" | FR-CFL-01 |
| 선택 종목 전부 상시시험 | 타임라인 미표시. 상시시험 카드만 | FR-TML-09, FR-CFL-07 |
| 회차 일정 미공고 | 해당 행에 "2027년 일정 미공고" 텍스트. 막대 없음 | FR-TML-10 |
| URL에 잘못된 코드 포함 | 유효한 종목만 렌더. 오류 화면 없음. "일부 시험을 찾지 못했어요" 안내 | FR-STA-05 |
| URL에 코드 없음 | S-01로 리다이렉트 | FR-SEL-06 |
| 특정 종목 데이터 수집 실패 | 해당 행에 "최종 확인: N일 전" 인라인 배지 | FR-DAT-07 |
| `.ics` 대상 이벤트 0건 | "캘린더에 담을 확정 일정이 없어요" 안내. 버튼 비활성 | FR-EXP-05 |
| 비로그인 상태에서 저장 시도 | 로그인 모달. 취소 시 선택 상태 유지 | FR-ACC-04·08 |
| 로그인 후 복귀 | 저장 직전의 선택 상태와 스크롤 위치 복원 | FR-STA-01 |

### 4.6 모바일 대응

| 항목 | 처리 |
|---|---|
| 가로축 | 월 라벨만(8월·9월…). 일 단위 눈금 없음 |
| 세로축 라벨 | `short` 우선, 최대 5자. 초과 시 말줄임 |
| 가로 스크롤 | 사용하지 않음. 6개월을 화면 폭에 맞춤 · FR-TML-13 |
| 이벤트 상세 | 탭 시 하단 시트 |
| 축 이동 | 좌우 화살표 버튼. 스와이프는 보조 |

**가로 스크롤을 금지하는 이유**: 스크롤로 6개월을 나눠 보면 "10월에 뭐가 몰려 있나"를 한 번에 볼 수 없다. 그 순간 이 서비스는 존재 이유를 잃는다. 6개월이 화면에 안 들어가면 라벨을 줄이고, 그래도 안 되면 표시 구간을 4개월로 줄인다 — 스크롤은 답이 아니다.

## 6. 로그인 모달

### 6.1 목적

**선택 상태를 잃지 않으면서** 최소 마찰로 로그인시킨다. 별도 페이지로 이동하지 않는 이유가 이것이다.

### 6.2 구성

```
┌────────────────────────────────────┐
│  이 조합을 저장하려면 로그인이 필요해요  │
│                                    │
│  [  구글로 계속하기  ]               │
│  [  카카오로 계속하기  ]             │
│                                    │
│  ☐ 만 14세 이상입니다 (필수)          │
│                                    │
│  닉네임만 받아요. 이메일·전화번호는     │
│  받지 않습니다.  개인정보 처리방침 ↗   │
│                                    │
│              [나중에 하기]           │
└────────────────────────────────────┘
```

| 요소 | 명세 | 요구사항 |
|---|---|---|
| 소셜 버튼 | 구글·카카오 2개. 동등한 위상으로 배치 | FR-ACC-01 |
| 만 14세 확인 | 체크 필수. 미체크 시 버튼 비활성 | FR-ACC-07 |
| 수집 항목 고지 | "닉네임만 받아요" 명시 + 처리방침 링크 | FR-ACC-03, NFR-PRIV-02 |
| 나중에 하기 | 모달 닫기. 선택 상태 유지 | FR-ACC-08 |

### 6.3 상태·예외

| 상태 | 처리 |
|---|---|
| 만 14세 미만 체크 시도 | 체크박스를 해제 상태로 두고 "만 14세 미만은 가입할 수 없어요" 안내 |
| 소셜 인증 취소·실패 | 모달 유지 + "로그인이 취소됐어요". 선택 상태 보존 |
| 카카오 닉네임 미제공 | 기본 표시명으로 대체. 오류 처리하지 않음 |
| 최초 로그인 | 별도 가입 화면 없이 즉시 완료 후 원래 동작(저장) 이어서 실행 |

**설계 의도**: 회원가입 폼이 없다. 소셜 인증이 곧 가입이고, 만 14세 확인 체크 하나만 추가된다. 인증 직후 사용자가 원래 하려던 동작(조합 저장)이 자동으로 이어져야 한다 — 로그인만 되고 아무 일도 안 일어나면 마찰이 두 배가 된다.

## 7. S-06 내 저장 목록

### 7.1 구성

```
┌──────────────────────────────────────────────┐
│  내 저장 목록                    만두 ▾        │
├──────────────────────────────────────────────┤
│  하반기 공채 준비                              │
│  전기기사 · 산업안전기사 · 토익                 │
│  ⚠ 충돌 1건        [열기]  [이름 변경]  [삭제]  │
│                                              │
│  기능사 3종                                   │
│  지게차 · 굴착기 · 제과                        │
│  충돌 없음          [열기]  [이름 변경]  [삭제]  │
│                                              │
│  ── 계정 ──────────────────────────         │
│  구글로 로그인됨 · 저장된 정보: 닉네임            │
│  [로그아웃]              [탈퇴하기]             │
└──────────────────────────────────────────────┘
```

| 요소 | 명세 | 요구사항 |
|---|---|---|
| 저장 목록 카드 | 이름 + 종목명 나열 + 충돌 건수 요약 | FR-ACC-04·05 |
| 열기 | 해당 조합으로 `/timeline` 이동 | FR-STA-01 |
| 이름 변경 · 삭제 | 인라인 처리 | FR-ACC-04 |
| 계정 정보 | 로그인 제공자 + 저장된 개인정보 항목 표시 | NFR-PRIV-02 |
| 탈퇴하기 | 확인 모달 → 즉시 영구 삭제 | FR-ACC-06, NFR-PRIV-05 |

### 7.2 상태·예외

| 상태 | 처리 |
|---|---|
| 저장 목록 0개 | "저장한 조합이 없어요" + 종목 선택으로 가는 링크 |
| 저장 상한 도달 | 추가 저장 시 "저장은 최대 N개까지 할 수 있어요" |
| 비로그인 접근 | S-01로 리다이렉트 + 로그인 모달 |
| 백엔드 응답 실패 | "목록을 불러오지 못했어요. 다시 시도" — 조회 기능은 영향 없음 |

### 7.3 탈퇴 처리

| 단계 | 처리 | 근거 |
|---|---|---|
| 확인 모달 | 삭제되는 항목을 명시. "저장 목록 2개와 계정 정보가 즉시 삭제됩니다" | |
| 소셜 연결 해제 | 제공자 연결 해제 API 호출 | FR-ACC-06 |
| 데이터 삭제 | 계정·세션·저장 목록 **영구 삭제**. 플래그 처리 아님 | NFR-PRIV-05 |
| 완료 안내 | 삭제 완료 표시 후 홈으로 | |

**`deleted_at` 플래그만 세우는 방식은 파기가 아니다.** 개인정보보호법 제21조는 지체 없는 파기를, 시행령 제16조는 복원 불가능한 영구 삭제를 요구한다. 소셜 제공자 ID도 개인정보이므로 삭제 대상이다.
