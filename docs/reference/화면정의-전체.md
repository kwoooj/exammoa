# 화면 정의서

문서 버전 1.1.0 · 2026-08-14 · 대상 범위: 캘린더 중심 정보 허브형 웹 MVP

---

## 0. 문서 목적

이 문서는 로그인 없는 시험 일정 정보 서비스 **시험모아**의 화면 구조와 사용자 경험을 정의한다.

시험모아의 핵심 목적은 개인 일정을 관리하는 것이 아니다.

> 여러 기관에 흩어진 시험 일정과 접수 정보를 한곳에서 검색·비교하고, 필요한 순간 공식 사이트로 바로 이동하게 한다.

모든 화면은 아래 네 가지 사용자 질문에 빠르게 답해야 한다.

1. 찾는 시험이 있는가?
2. 지금 접수할 수 있는가?
3. 접수와 시험이 언제인가?
4. 어디에서 공식 정보를 확인하거나 접수하는가?

### 0.1 제품 원칙

- 로그인 없이 모든 핵심 정보를 볼 수 있어야 한다.
- 공식 기관으로의 연결이 화면의 명확한 종착점이어야 한다.
- D-Day는 개인 관리 기능이 아니라 일정의 긴급도를 설명하는 보조 정보다.
- 사용자가 시험을 선택하지 않아도 사이트의 가치가 보여야 한다.
- 같은 일정을 공유하는 시험은 시행그룹 단위로 중복을 제거하되, 사용자가 검색한 시험명은 유지한다.
- 수집 시각, 출처, 오래된 데이터 여부를 숨기지 않는다.
- 카드 장식보다 검색, 상태, 날짜, 기관명, 공식 링크를 우선한다.
- 공식 일정은 월간 캘린더를 기본 표현으로 사용하고, 목록은 상세·접근성 대체 수단으로 제공한다.
- 사용자가 가정한 날짜는 공식 일정과 시각·문구·저장 위치를 분리한다.

### 0.2 MVP에서 하지 않는 것

- 로그인, 회원가입, 마이페이지
- 서버에 저장하는 관심 시험
- 공식 일정 확인 전에 응시 예정일 입력을 요구하는 흐름
- 개인 D-Day 대시보드
- 일정 충돌 자동 판정
- 푸시 알림과 이메일 알림
- 후기, 게시판, 합격 인증
- 자격증 강의·교재 광고

브라우저에만 저장되는 가정 날짜·예약일, 캘린더 파일, 최근 본 시험은 공식 캘린더가 완성된 뒤 별도 우선순위로 검토한다.

## 1. 정보 구조

```text
/                                  S-01 홈
├─ /exams                          S-02 시험 일정 탐색
│  └─ ?q=&category=&status=&date=
├─ /exam/{slug}                    S-03 시험 상세
├─ /calendar?exams={slug,...}      S-04 통합 캘린더
├─ /about                          S-05 서비스 소개·데이터 출처
├─ /privacy                        S-06 개인정보·로컬 저장 안내
└─ /404                            S-07 찾을 수 없음
```

### 1.1 화면별 역할

| 화면 | 역할 | 가장 중요한 행동 |
|---|---|---|
| S-01 홈 | 검색과 주요 일정 발견 | 시험 검색 또는 상태별 목록 진입 |
| S-02 시험 일정 탐색 | 조건에 맞는 시험 찾기 | 상세 확인 또는 공식 사이트 이동 |
| S-03 시험 상세 | 한 시험의 전체 일정과 출처 확인 | 공식 정보·원서접수 이동 |
| S-04 통합 캘린더 | 공식 일정을 월간 격자에서 탐색하고 선택한 시험을 비교 | 날짜 상세 확인, 공식 사이트 이동, 캘린더 공유 |
| S-05 소개·출처 | 데이터 범위와 신뢰 방식 설명 | 출처 확인 |
| S-06 개인정보 | 로그인 없는 상태 저장 방식을 설명 | 로컬 데이터 삭제 |
| S-07 404 | 잘못된 URL에서 복귀 | 시험 검색 |

### 1.2 주요 사용자 동선

#### 검색 유입

```text
검색엔진
→ S-03 시험 상세
→ 현재 접수 상태 확인
→ 공식 원서접수 또는 공식 공고
```

#### 직접 방문

```text
S-01 홈
→ 시험명 검색 또는 상태별 바로가기
→ S-02 탐색 결과
→ S-03 상세
→ 공식 사이트
```

#### 캘린더 탐색·비교

```text
S-02 탐색 결과
→ 캘린더에 1~6개 추가
→ S-04 통합 캘린더
→ 공식 일정 비교
→ 필요할 때만 가정 날짜 표시 또는 공식 사이트 이동
```

검색 유입에서는 S-03이 첫 화면이고, 직접 방문에서는 S-01과 S-02가 첫 화면이다. 어떤 경로로 들어와도 두 번 이내의 행동으로 공식 사이트에 도달할 수 있어야 한다.

## 2. 공통 레이아웃

### 2.1 헤더

#### 데스크톱

```text
┌──────────────────────────────────────────────────────────────┐
│ 시험모아   [시험명·시행기관 검색________________]  일정 찾기  소개 │
└──────────────────────────────────────────────────────────────┘
```

| 요소 | 명세 |
|---|---|
| 워드마크 | `시험모아`. 클릭 시 홈으로 이동 |
| 통합 검색 | 시험명, 약칭, 시행기관 검색. S-01에서는 생략하거나 축소 가능 |
| 일정 찾기 | S-02로 이동 |
| 소개 | S-05로 이동 |
| 캘린더 | S-04로 이동. 선택한 시험이 있으면 `캘린더 3` 형태로 노출 |

#### 모바일

- 한 줄 헤더에 워드마크와 검색 아이콘만 둔다.
- 검색 아이콘을 누르면 전체 폭 검색창이 열린다.
- 앱형 하단 내비게이션은 사용하지 않는다.
- 캘린더에 담은 시험이 있을 때만 화면 하단에 `3개 캘린더로 보기` 고정 버튼을 표시한다.

### 2.2 통합 검색 동작

검색 대상:

- `Exam.name`
- `Exam.short`
- `ScheduleGroup.agency`
- 카테고리명

검색 우선순위:

1. 정확한 시험명
2. 약칭 정확 일치
3. 시험명 앞부분 일치
4. 시험명 부분 일치
5. 시행기관 일치

두 글자 이상 입력하면 자동완성을 보여준다. Enter를 누르거나 `전체 결과 보기`를 선택하면 S-02로 이동한다.

자동완성 항목에는 시험명, 기관명, 현재 상태를 표시한다.

```text
정보처리기사
한국산업인력공단 · 접수 예정
```

### 2.3 푸터

| 요소 | 내용 |
|---|---|
| 서비스 설명 | 여러 기관의 시험 일정을 모아 보여주는 비공식 정보 서비스 |
| 최종 수집 | 전체 배치가 마지막으로 완료된 날짜 |
| 데이터 출처 | S-05로 이동 |
| 면책 | 일정은 참고용이며 공식 공고가 우선 |
| 개인정보 | S-06으로 이동 |

운영용 수집 로그와 소스별 오류 전문은 푸터에 직접 펼치지 않는다.

### 2.4 공통 데이터 상태

| 상태 | 표시 원칙 |
|---|---|
| 전체 데이터 정상 | 별도 성공 배지 없음 |
| 특정 소스가 오래됨 | 해당 시험에만 `최종 확인 N일 전` 표시 |
| 이전 데이터를 유지 중 | `이전 확인 정보를 표시하고 있어요` + 공식 링크 |
| 일정 미공고 | 빈 표 대신 `아직 공식 일정이 발표되지 않았어요` |
| 일부 필드 없음 | 없는 행 자체를 숨기며 임의 날짜를 추정하지 않음 |
| 전체 데이터 로딩 실패 | 검색과 목록 대신 오류 안내 + 다시 시도 |
| 오프라인 | 캐시가 있으면 오래된 상태로 표시, 없으면 연결 안내 |

## 3. 상태 체계

상태는 회차의 이벤트와 오늘 날짜를 기준으로 화면에서 계산한다. 저장 데이터에 D-Day 또는 파생 상태를 넣지 않는다.

### 3.1 대표 상태

| 우선순위 | 상태 | 조건 | 대표 문구 |
|---:|---|---|---|
| 1 | 접수 마감 임박 | 접수 종료까지 3일 이하 | `접수 D-2` |
| 2 | 접수 중 | 접수 시작 ≤ 오늘 ≤ 접수 종료 | `접수 중` |
| 3 | 시험 기간 | 시험 시작 ≤ 오늘 ≤ 시험 종료 | `시험 진행 중` |
| 4 | 접수 예정 | 가장 가까운 미래 이벤트가 접수 | `9월 21일 접수 시작` |
| 5 | 시험 예정 | 접수는 끝났고 미래 시험이 있음 | `10월 24일 시험 시작` |
| 6 | 결과 발표 예정 | 미래 이벤트가 발표만 남음 | `12월 11일 발표` |
| 7 | 상시시험 | `cadence=rolling` | `상시시험` |
| 8 | 일정 미공고 | 확정 회차 없음 | `일정 미공고` |
| 9 | 종료 | 모든 이벤트가 과거 | `올해 일정 종료` |

### 3.2 상태 표현

- 색상만으로 상태를 구분하지 않는다.
- `접수 중`과 `접수 D-N`만 강조색을 사용한다.
- 접수 예정·시험 예정은 중립색을 사용한다.
- 마감·종료는 채도를 낮추되 읽을 수 있는 명암을 유지한다.
- 긴급 상태는 결과 정렬에도 반영한다.

## 4. 공통 시험 목록 항목

S-01, S-02, S-03 관련 시험에서 같은 기본 구조를 사용한다.

```text
┌──────────────────────────────────────────────────────────┐
│ [접수 중]                                                │
│ 정보처리기사                           한국산업인력공단     │
│ 실기 원서접수  2026.09.21 ~ 2026.10.19                  │
│ 실기시험      2026.10.24 ~ 2026.11.13                  │
│ 최종 확인 2026.08.14        [상세 일정] [원서접수 ↗]      │
└──────────────────────────────────────────────────────────┘
```

### 4.1 필수 정보

- 대표 상태
- 시험명
- 시행기관
- 가장 가까운 접수 일정
- 가장 가까운 시험 일정
- 최종 확인 날짜
- 상세 일정 링크
- 공식 링크

### 4.2 공식 링크 우선순위

1. `ScheduleGroup.applyUrl`이 있으면 `원서접수`
2. `ScheduleGroup.agencyUrl`이 있으면 `공식 정보`
3. 둘 다 없으면 버튼 대신 `공식 링크 확인 중`

외부 링크에는 시행기관을 예측할 수 있는 접근성 이름을 제공한다.

예:

- 화면 문구: `원서접수 ↗`
- 접근성 이름: `한국산업인력공단 정보처리기사 원서접수 새 창 열기`

### 4.3 목록 항목에서 하지 않는 것

- D-Day 숫자만 크게 보여주지 않는다.
- 모든 회차를 한 항목에 펼치지 않는다.
- 공식 일정을 보기 전에 계획 날짜 입력을 요구하지 않는다.
- 기관명이나 날짜보다 장식 아이콘을 강조하지 않는다.

## 5. S-01 홈

### 5.1 목적

처음 방문한 사용자가 3초 안에 서비스 용도를 이해하고, 시험명 검색 또는 현재 상태 탐색을 바로 시작하게 한다.

### 5.2 데스크톱 레이아웃

```text
┌──────────────────────────────────────────────────────────────┐
│ 헤더                                                        │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  흩어진 시험 일정을 한곳에서 확인하세요                        │
│  접수 기간과 시험일을 비교하고 공식 접수처로 바로 이동할 수 있어요 │
│                                                              │
│  [ 시험명 또는 시행기관 검색_______________________ ][검색]    │
│                                                              │
│  [현재 접수 중] [곧 접수 시작] [이번 달 시험] [상시시험]       │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│  지금 접수할 수 있는 시험                         [전체 보기]  │
│  ─ 정보처리기사 · 실기 접수 10.19까지        [원서접수 ↗]      │
│  ─ TOEIC · 정기접수 08.16까지               [원서접수 ↗]      │
│  ─ KBS한국어 · 접수 08.20까지                [공식 정보 ↗]     │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│  분야별 시험 찾기                                             │
│  IT·개발  사무·회계  금융·은행  안전·환경  전기·기계  서비스 …  │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│  2026년 8월 주요 일정                          [전체 캘린더]  │
│  월   화   수   목   금   토   일                             │
│       10   11   12   13   14   15   16                      │
│                      오늘       TOEIC 접수 마감                │
│       17   18   19   20   21   22   23                      │
│                 KBS 접수 마감          기사 필기시험           │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│  68개 시험 · 25개 시행그룹 · 최종 확인 2026.08.20             │
│  [데이터 출처와 갱신 방식]                                    │
└──────────────────────────────────────────────────────────────┘
```

### 5.3 섹션 정의

#### A. 검색 히어로

- 첫 화면에서 가장 큰 상호작용 요소는 검색창이다.
- 헤드라인은 두 줄을 넘지 않는다.
- 일러스트, 목업 이미지, 장식용 그래픽을 사용하지 않는다.
- `로그인 없이`는 제품 장점이지만 헤드라인보다 아래 보조 문구로만 사용한다.

#### B. 상태별 바로가기

| 바로가기 | 이동 |
|---|---|
| 현재 접수 중 | `/exams?status=open` |
| 곧 접수 시작 | `/exams?status=upcoming` |
| 이번 달 시험 | `/exams?date={current-month}&kind=exam` |
| 상시시험 | `/exams?cadence=rolling` |

버튼은 최대 네 개만 노출한다. 카테고리 전체를 칩 형태로 함께 섞지 않는다.

#### C. 지금 접수할 수 있는 시험

- 접수 종료가 가까운 순으로 최대 5개 노출한다.
- 같은 시행그룹이라도 시험명이 다르면 사용자가 인식하는 종목 단위로 보여준다.
- 한 그룹에 많은 종목이 동시에 접수 중이면 최대 3개까지만 개별 노출하고 `같은 일정의 시험 N개 더 보기`로 묶는다.
- 각 행에서 공식 접수 링크로 직접 이동할 수 있다.

#### D. 분야별 시험

- 카테고리 이름과 대표 시험 2~3개만 표시한다.
- 카테고리를 선택하면 S-02 필터 결과로 이동한다.
- 첫 화면에서 68개 종목 전체를 펼치지 않는다.

#### E. 이번 달 캘린더 미리보기

- 월간 격자를 사용해 이번 달의 주요 접수 마감과 시험 시작일을 보여준다.
- 홈에서는 모든 기간 막대를 펼치지 않는다. 접수 마감, 하루짜리 시험, 기간 시험의 시작일만 요약한다.
- 하루에 최대 2건만 노출하고 나머지는 `외 N건`으로 접는다.
- 날짜나 일정을 선택하면 S-04의 같은 달·같은 필터 상태로 이동한다.
- `전체 캘린더`를 통해 S-04로 이동한다.
- 발표 일정은 홈 미리보기에서 제외한다.
- 시행그룹 중복은 한 건으로 접고 관련 시험 수를 표시한다.

### 5.4 상태·예외

| 상태 | 처리 |
|---|---|
| 접수 중 시험 없음 | `현재 접수 중인 시험이 없어요` + 곧 시작하는 시험 3개 |
| 가까운 일정 없음 | 다음 확정 일정이 있는 달을 표시 |
| 특정 카테고리 데이터 없음 | 카테고리 자체는 숨김 |
| 검색 결과 자동완성 없음 | S-02 전체 검색으로 이동할 수 있는 버튼 제공 |

### 5.5 모바일

- 검색 히어로가 첫 화면 높이의 절반을 넘지 않는다.
- 상태별 바로가기는 2열 버튼으로 배치한다.
- `지금 접수 중` 목록은 가로 캐러셀이 아니라 세로 목록이다.
- 분야별 시험은 카테고리명만 먼저 보여주며 전체 시험 칩을 펼치지 않는다.
- 캘린더 미리보기는 7열을 유지하되 일정 라벨은 한 줄로 제한한다.

## 6. S-02 시험 일정 탐색

### 6.1 목적

사용자가 시험명, 분야, 기관, 날짜, 상태 조건으로 원하는 시험을 찾고 통합 캘린더에 올릴 후보를 만든다.

### 6.2 URL

```text
/exams
/exams?q=정보
/exams?category=it
/exams?status=open
/exams?date=2026-10
/exams?category=it&status=upcoming&sort=deadline
```

검색과 필터 상태는 URL에 반영한다. 새로고침, 뒤로 가기, 링크 공유 후에도 결과가 유지되어야 한다.

### 6.3 레이아웃

```text
┌──────────────────────────────────────────────────────────────┐
│ 시험 일정 찾기                                               │
│ [시험명·시행기관 검색_______________________________][검색]   │
│                                                              │
│ 분야 [전체⌄]  상태 [접수 중⌄]  기간 [2026.08~2026.10⌄]       │
│ 유형 [전체⌄]  기관 [전체⌄]                   [필터 초기화]    │
│                                                              │
│ 접수 중인 시험 12개                         마감 가까운 순⌄   │
├──────────────────────────────────────────────────────────────┤
│ □ 정보처리기사 · 한국산업인력공단                             │
│   실기 접수 09.21~10.19 · 실기시험 10.24~11.13              │
│   [상세 일정]                              [원서접수 ↗]       │
├──────────────────────────────────────────────────────────────┤
│ □ SQLD · 한국데이터산업진흥원                                 │
│   접수 08.24~08.28 · 시험 09.12                             │
│   [상세 일정]                              [공식 정보 ↗]      │
└──────────────────────────────────────────────────────────────┘
│                [선택한 2개 캘린더로 보기]                     │
└──────────────────────────────────────────────────────────────┘
```

### 6.4 필터

| 필터 | 값 |
|---|---|
| 분야 | 전체 + `categories` |
| 상태 | 접수 중, 접수 예정, 시험 예정, 상시시험, 일정 미공고 |
| 기간 | 이번 달, 다음 달, 3개월, 사용자 지정 |
| 일정 종류 | 접수, 시험, 발표 |
| 유형 | 정기, 고빈도, 상시 |
| 시행기관 | 현재 데이터에 존재하는 기관 |

모든 필터는 AND 조건으로 결합한다. 같은 필터 안에서 여러 값을 고를 때는 OR 조건이다.

### 6.5 정렬

기본 정렬은 아래 우선순위를 따른다.

1. 접수 마감 임박
2. 접수 중
3. 접수 예정일이 가까움
4. 시험 예정일이 가까움
5. 시험명 가나다순

사용자는 `마감 가까운 순`, `시험 가까운 순`, `시험명 순`으로 바꿀 수 있다.

### 6.6 캘린더 선택

- 시험 항목의 체크박스로 통합 캘린더에 추가한다.
- 1개만 선택해도 캘린더를 볼 수 있고, 비교 목적일 때는 최대 6개까지 선택한다.
- 선택 상태는 URL에 넣지 않고 현재 페이지 메모리에 유지해도 된다.
- `캘린더로 보기`를 누를 때 선택한 slug를 S-04 URL에 기록한다.
- 같은 시행그룹의 시험을 여러 개 선택하면 경고하지 않는다. S-04에서 같은 일정임을 설명한다.

### 6.7 상태·예외

| 상태 | 처리 |
|---|---|
| 결과 0개 | 적용된 필터 요약 + `필터 초기화` |
| 검색어 오타 | 자동 교정하지 않고 부분 일치 결과와 유사 시험 제안 |
| 선택 0개 | 캘린더 버튼 숨김 |
| 선택 1개 | `1개 캘린더로 보기` 활성 |
| 선택 6개 | 다른 항목 체크박스 비활성 + 최대 개수 안내 |
| 오래된 일정 포함 | 해당 항목 안에서만 갱신 경고 |

### 6.8 모바일

- 필터는 상단 `필터` 버튼을 누르면 하단 시트로 연다.
- 활성 필터만 검색창 아래에 제거 가능한 칩으로 표시한다.
- 시험명, 상태, 다음 접수일, 공식 링크가 첫 화면에 보이게 한다.
- 캘린더 선택이 있으면 하단 고정 버튼을 표시한다.

## 7. S-03 시험 상세

### 7.1 목적

검색엔진과 사이트 내부 검색으로 들어온 사용자에게 한 시험의 현재 상태, 회차별 일정, 공식 출처를 설명하고 공식 사이트로 연결한다.

### 7.2 URL과 SEO

| 항목 | 값 |
|---|---|
| URL | `/exam/{slug}` |
| title | `정보처리기사 2026 시험일정·원서접수 | 시험모아` |
| description | 가장 가까운 접수 또는 시험 일정 포함 |
| canonical | 연도 파라미터가 있어도 기본 slug URL |
| 구조화 데이터 | 제공 가능한 범위에서 Event 또는 ItemList 검토 |

slug는 URL 인코딩된 한글 또는 안정적인 영문 slug 중 하나로 통일한다. 화면 구현 단계에서 혼용하지 않는다.

### 7.3 레이아웃

```text
┌──────────────────────────────────────────────────────────────┐
│ IT·개발 > 정보처리기사                                       │
│                                                              │
│ 정보처리기사                                                 │

│ 최종 확인 2026.08.14                                        │

│ [접수 예정] 실기 원서접수                                     │
```

### 7.4 상단 요약

- 시험명과 기관명을 가장 먼저 보여준다.
- 다음 행동과 관련된 대표 이벤트 한 건만 강조한다.
- 대표 이벤트는 상태 우선순위에 따라 선택한다.
- 공식 CTA는 데이터가 있을 때만 표시한다.
- 외부 링크는 새 창으로 열고 외부 이동 표시를 제공한다.

### 7.5 시험 일정 캘린더

- 기본은 현재 진행 중이거나 가장 가까운 회차다.
- 이전 회차는 회차 선택 메뉴에서 볼 수 있다.
- 월간 격자를 기본 보기로 사용한다.
- 필기·실기 일정은 같은 달력에 표시하되 라벨에 단계를 포함한다.
- `start !== end`인 기간 시행은 주 경계를 이어지는 연속 막대로 표시한다.
- 하루짜리 시험은 채운 점 또는 하루 폭 블록으로 표시한다.
- 접수는 테두리 막대, 시험은 채운 막대, 발표는 빈 원으로 구분한다.
- 현재 진행 중인 막대는 굵기와 상태 문구로 강조한다.
- 과거 일정은 숨기지 않고 채도만 낮춘다.
- 여러 차수 접수는 `정기접수`, `추가접수`를 분리해 표시한다.
- 일정을 선택하면 달력 아래 상세 패널에 전체 날짜, 상태, 공식 링크를 표시한다.
- 같은 정보를 날짜순 표로 제공하되 기본은 접힘 상태로 둔다.

### 7.6 계획 기능 진입

- 시험 상세의 기본 상태에는 개인 계획 입력을 노출하지 않는다.
- 사용자가 통합 캘린더에 시험을 추가한 뒤 `내 계획 표시`를 켠 경우에만 계획 기능을 제공한다.
- 기간 시행은 공식 기간 안에서만 `가정 날짜`를 표시할 수 있다.
- 하루짜리 공식 시험은 날짜 선택을 받지 않고 해당 날짜를 그대로 사용한다.
- 가정 날짜는 예약이나 접수를 보장하지 않는다는 안내를 함께 표시한다.

### 7.7 상시시험

`cadence=rolling` 또는 `mode=rolling`이면 날짜표를 만들지 않는다.

```text
컴퓨터활용능력 1급
상시시험

확정된 연간 시험일이 없는 상시시험이에요.
접수와 시험 가능 일자는 공식 사이트에서 확인해 주세요.

접수 규칙: 시험일 4일 전까지
마지막 규칙 확인: 2026.08.01

[공식 시험일 확인 ↗] [원서접수 ↗]
```

규칙 확인일이 오래되면 `공식 사이트에서 최신 규칙을 확인해 주세요`를 함께 표시한다.

상시시험의 계획 입력은 공식 일정과 분리한다.

- 예약 전에는 정확한 날짜를 임의로 받지 않고 `목표 월 표시`만 제공한다.
- 공식 사이트에서 예약한 사용자는 `예약한 시험일 표시`로 정확한 날짜를 저장할 수 있다.
- 사용자가 입력한 날짜는 실제 예약 가능일 검증 결과가 아님을 명시한다.
- 캘린더에는 목표 월을 날짜 막대로 만들지 않는다. 예약한 시험일만 개인 계획 마커로 표시한다.

### 7.8 일정 미공고

```text
2027년 일정이 아직 발표되지 않았어요.
공식 기관에 일정이 게시되면 시험모아에도 반영됩니다.

[공식 시험정보 확인 ↗]
```

빈 일정표나 비활성 버튼을 보여주지 않는다.

### 7.9 출처·신뢰

| `conf` | 표시 |
|---|---|
| verified | 기본 출처 문구. 별도 신뢰 배지 없음 |
| parsed | `공식 페이지에서 수집` + 출처 링크 |
| manual | `수동 확인 정보` + 확인 날짜 |
| stale | 상단 요약과 출처 영역에 경고 |

운영 용어인 `parsed`, `manual`, `stale`을 그대로 사용자에게 노출하지 않는다.

### 7.10 관련 시험

- 같은 카테고리에서 최대 4개를 추천한다.
- 현재 시험과 같은 시행그룹이면 `일정이 같은 시험`이라고 명시한다.
- 추천 알고리즘처럼 과장하지 않고 `같은 분야의 시험`이라는 중립 문구를 쓴다.

### 7.11 모바일

- 시험명, 상태, 다음 일정, 공식 CTA가 첫 화면 안에 들어와야 한다.
- 공식 CTA는 화면 하단 고정이 아니라 본문 상단에 둔다.
- 회차 선택은 전체 폭 선택 메뉴로 제공한다.
- 월간 캘린더는 7열을 유지하고 일정 라벨은 한 줄로 제한한다.
- 날짜를 선택하면 일정 상세를 하단 시트로 연다.
- 접근성 대체 표는 캘린더 아래에서 펼칠 수 있다.

## 8. S-04 통합 캘린더

### 8.1 목적

공식 시험 일정을 월간 격자에서 탐색하고, 선택한 1~6개 시험의 접수·시험·발표 일정을 같은 시간축에서 비교한다.

비교는 별도의 제품 목적이 아니라 통합 캘린더의 선택 상태다. 서비스가 충돌을 대신 판정하지 않고, 사용자가 공식 기간을 본 뒤 현실적인 날짜를 판단하도록 돕는다.

현재 발행 데이터에서는 시험 이벤트 260개 중 164개가 기간 시행이고 중앙 기간은 5일이다. 미래 시험이 있는 시행그룹 조합의 다수에서 한 번 이상 기간이 겹치지만, 겹침 자체는 응시 불가를 의미하지 않는다. 따라서 경고 엔진보다 캘린더와 선택적 계획 표시가 적합하다.

### 8.2 URL

```text
/calendar
/calendar?month=2026-10
/calendar?exams=정보처리기사,sqld,토익&month=2026-10
/calendar?category=it&kinds=reg,exam
```

- 월, 선택 시험, 카테고리, 일정 종류는 URL에서 복원한다.
- 개인 가정 날짜와 예약일은 공유 URL에 기본 포함하지 않는다.
- 로그인이나 서버 저장을 요구하지 않는다.

### 8.3 화면 모드

#### 전체 일정 모드

- 시험 선택 없이도 접근할 수 있다.
- 검색·분야·기관·일정 종류 필터에 해당하는 공식 일정을 보여준다.
- 하루에 최대 3개의 라벨만 표시하고 나머지는 `외 N건`으로 접는다.
- 기간 막대가 과밀하면 시행그룹 단위로 중복을 제거한다.

#### 선택 비교 모드

- 1~6개 시험을 선택하면 해당 시험만 캘린더에 남긴다.
- 시험 1개도 정상 상태이며 상세 페이지보다 넓은 월간 맥락을 제공한다.
- 시험 2개 이상일 때 비교 링크 복사를 제공한다.
- 선택한 시험은 상단 칩에서 제거하거나 추가할 수 있다.

### 8.5 공식 일정 표현

| 일정 | 달력 표현 | 선택 시 상세 |
|---|---|---|
| 접수 기간 | 테두리 막대 | 시작·종료·추가접수 여부·원서접수 링크 |
| 기간 시험 | 채운 막대 | 공식 시험 가능 기간·단계·공식 정보 링크 |
| 하루 시험 | 채운 점 또는 하루 폭 블록 | 정확한 시험일·단계 |
| 발표 | 빈 원 | 발표일·공식 결과 링크가 있으면 제공 |
| 오늘 | 날짜 테두리 | `오늘` 텍스트 병행 |

- 주가 바뀌어도 같은 이벤트의 막대가 이어지는 것처럼 표현한다.
- 막대 안에는 시험 약칭과 이벤트 종류를 함께 표시한다.
- 일정이 같은 시행그룹은 하나의 막대로 접고 관련 시험명을 상세 패널에 표시한다.
- 공식 일정에는 사용자 계획과 같은 마름모 표현을 사용하지 않는다.

### 8.6 날짜·일정 상세 패널

- 데스크톱에서는 캘린더 오른쪽 패널을 사용한다.
- 날짜를 선택하면 해당 날짜의 모든 공식 일정을 표시한다.
- 특정 막대를 선택하면 시험명, 기관, 전체 기간, 상태, 공식 링크를 표시한다.
- 패널이 열려도 캘린더 월과 필터 상태는 유지한다.
- 모바일에서는 같은 내용을 하단 시트로 제공한다.

### 8.7 선택적 내 계획 레이어

`내 계획`은 P2 기능이며 공식 일정과 분리된 로컬 보조 기능이다.

| 시험 형태 | 입력 방식 | 캘린더 표시 |
|---|---|---|
| 하루짜리 공식 시험 | 입력 없음. 공식 날짜 사용 | 공식 시험 표시만 |
| 기간 시행 | 공식 기간 안에서 `가정 날짜` 선택 | 마름모 + `가정` |
| 고빈도 정기시험 | 공식 회차 중 하나 선택 | 선택 회차에 계획 마커 |
| 상시시험·예약 전 | `목표 월`만 선택 | 캘린더 날짜에는 표시하지 않음 |
| 상시시험·예약 후 | `예약한 시험일` 입력 | 마름모 + `예약일` |

계획 레이어 규칙:

- 기본은 꺼짐 상태다.
- `가정 날짜`는 공식 예약이 아니라 개인 계획용임을 입력 시점에 명시한다.
- 기간 밖 날짜는 선택할 수 없다.
- 상시시험 목표 월을 정확한 날짜나 기간 막대로 변환하지 않는다.
- 예약일은 사용자가 공식 사이트에서 확보한 날짜를 기록하는 용도이며 서비스가 가능 여부를 검증하지 않는다.
- 같은 날짜에 두 개 이상의 계획 마커가 있으면 `이 날 다른 시험 계획이 있어요`라고 알리되 입력을 막지 않는다.
- 계획 데이터는 브라우저에만 저장하고 출처·공식 일정 데이터와 합치지 않는다.
- 로컬 계획을 삭제하는 기능과 저장 위치 안내를 제공한다.

### 8.8 시행그룹 중복

일정의 실제 주체는 종목이 아니라 `ScheduleGroup`이다.

같은 시행그룹의 시험이 여러 개 선택되면 달력 막대를 반복하지 않는다.

```text
국가기술자격 기사 제3회
정보처리기사 · 산업안전기사 외 2개
```

상세 패널에는 선택한 시험명을 모두 표시해 선택이 사라졌다고 오해하지 않게 한다.

### 8.9 상시·고빈도 시험

- 상시시험은 공식 날짜가 없으므로 달력 막대를 만들지 않는다.
- 캘린더 상단 또는 상세 패널에 규칙 카드와 공식 예약 링크를 제공한다.
- 고빈도 시험은 같은 날짜 칸의 라벨을 모두 펼치지 않고 `TOEIC 외 N건`처럼 접는다.
- 고빈도 일정의 전체 날짜는 날짜순 일정표에서 확인할 수 있다.

### 8.10 접근성 대체 일정표

캘린더 아래에 동일한 공식 일정을 날짜순 표로 제공한다.

| 날짜 | 시험 | 구분 | 상태 | 공식 |
|---|---|---|---|---|
| 09.21~10.19 | 정보처리기사 | 실기 접수 | 접수 예정 | 원서접수 |
| 09.12 | SQLD | 시험 | 시험 예정 | 공식 정보 |

- 기본은 접힘 상태지만 키보드와 스크린리더로 접근할 수 있다.
- 계획 레이어가 켜지면 별도 열에 `가정 날짜` 또는 `예약일`을 표시한다.

### 8.11 캘린더에서 하지 않는 것

- 기간이 겹친다는 이유만으로 위험·충돌 경고를 만들지 않는다.
- 겹치는 영역 전체를 경고색으로 칠하지 않는다.
- 공식 일정과 사용자 계획을 같은 모양으로 표시하지 않는다.
- 상시시험에 존재하지 않는 공식 날짜를 생성하지 않는다.
- 캘린더를 보기 위해 계획 날짜 입력을 요구하지 않는다.
- 선택한 시험을 저장하거나 비교하기 위해 로그인을 요구하지 않는다.

### 8.12 상태·예외

| 상태 | 처리 |
|---|---|
| 시험 선택 없음 | 전체 일정 모드 + 검색·필터 제공 |
| 선택 시험 1개 | 단일 시험 월간 캘린더 |
| 선택 시험 2~6개 | 선택 비교 모드 + 링크 복사 |
| 잘못된 slug 포함 | 유효한 시험만 표시 + `일부 시험을 찾지 못했어요` |
| 일정 미공고 포함 | 날짜 막대 없이 미공고 안내 |
| 전부 상시시험 | 빈 격자 대신 규칙 카드 목록과 공식 링크 |
| 하루 일정 3건 초과 | `외 N건` + 날짜 상세 패널 |
| 로컬 계획 저장 실패 | 공식 캘린더는 유지하고 계획만 저장되지 않았음을 안내 |

### 8.13 모바일

- 7열 월간 격자를 유지한다.
- 일정 라벨은 한 줄로 제한하고 시험 약칭을 우선한다.
- 날짜 선택 시 하단 시트에서 전체 일정과 공식 링크를 보여준다.
- 필터와 시험 추가는 각각 하단 시트로 연다.
- 계획 입력은 상세 시트 안에서만 시작한다.
- 가로 스크롤을 핵심 탐색 방식으로 사용하지 않는다.
- 일정이 많은 달에는 달력 아래 날짜순 목록을 함께 노출한다.

### 9.3 소스 목록

```text
한국산업인력공단
API · 마지막 확인 2026.08.14 · 47개 시험

YBM
```

## 10. S-06 개인정보·로컬 저장 안내

로그인과 회원 데이터가 없더라도 로컬 저장 또는 분석 도구를 사용한다면 안내 페이지를 둔다.

### 10.1 포함 내용

- 계정과 개인 프로필을 수집하지 않음
- 검색어 또는 방문 통계 수집 여부
- 캘린더 선택, 가정 날짜, 목표 월, 예약일, 최근 본 시험의 브라우저 저장 여부
- 저장된 로컬 데이터를 삭제하는 방법
- 외부 공식 사이트로 이동할 때 해당 기관 정책이 적용됨

분석 도구가 없다면 없는 사실을 명시한다. 향후 도입하면 이 문서를 먼저 갱신한다.

## 11. S-07 찾을 수 없음

```text
요청한 시험 정보를 찾지 못했어요.
```

- 운영 오류 코드나 원본 JSON 정보를 노출하지 않는다.

## 12. 반응형 기준

### 12.1 데스크톱

- 콘텐츠 최대 폭: 1120~1200px
- 검색 결과는 넓은 단일 열을 기본으로 한다.
- 필터가 많을 때만 좌측 필터 패널을 검토하되 MVP에서는 상단 필터를 사용한다.
- 목록 한 행 안에서 시험명, 핵심 날짜, 공식 CTA가 한눈에 연결되어야 한다.
- 통합 캘린더는 `월간 격자 + 우측 상세 패널` 2열을 기본으로 한다.

### 12.2 태블릿

- 필터를 두 줄로 감싸고 목록은 단일 열을 유지한다.
- 상세 화면의 상단 요약과 CTA를 세로로 쌓는다.
- 캘린더 상세 패널은 격자 아래로 이동한다.

### 12.3 모바일

- 본문 좌우 여백: 20px
- 최소 터치 영역: 44×44px
- 날짜 범위는 임의로 줄이지 않는다.
- 표는 카드로 변환하거나 세로 행으로 재배치한다.
- 가로 스크롤을 핵심 탐색 방식으로 사용하지 않는다.
- 외부 링크 CTA는 한 손으로 누르기 쉬운 전체 폭 버튼을 사용할 수 있다.
- 월간 캘린더는 7열을 유지하고 상세는 하단 시트로 제공한다.

## 13. 시각 디자인 원칙

시험모아는 앱 대시보드보다 검색 서비스와 공공정보 포털의 중간 인상을 목표로 한다.

### 13.1 기본 방향

- 배경은 흰색 또는 매우 옅은 중립색
- 본문은 짙은 차콜
- 공식 링크와 활성 필터에만 단일 블루 사용
- 오류·오래된 데이터에는 별도의 경고색 사용
- 카드보다 구분선, 간격, 타이포그래피로 정보 그룹을 나눔
- 모서리 반경은 8~12px 범위로 제한
- 그림자는 떠 있는 시트와 메뉴에만 사용

### 13.2 AI 생성형 UI처럼 보이지 않기 위한 제한

- 모든 정보를 둥근 카드에 넣지 않는다.
- 그라디언트, 유리 효과, 장식용 블러를 사용하지 않는다.
- 의미 없는 통계 숫자와 대시보드 차트를 만들지 않는다.
- 필터 외의 모든 문구를 pill 형태로 만들지 않는다.
- 긴 설명 문구보다 실제 날짜와 상태를 우선한다.
- 이모지를 아이콘 대신 사용하지 않는다.
- 하나의 화면에서 강조 버튼을 여러 개 경쟁시키지 않는다.

### 13.3 타이포그래피

| 용도 | 권장 크기 |
|---|---:|
| 페이지 제목 | 28~36px |
| 섹션 제목 | 20~24px |
| 시험명 | 17~20px |
| 본문·날짜 | 14~16px |
| 기관명·출처 | 12~14px |

한국어 본문은 지나치게 좁은 자간을 사용하지 않는다. 날짜는 숫자 폭이 안정적인 서체 설정을 검토한다.

## 14. 접근성

- 모든 기능은 키보드로 접근 가능해야 한다.
- 검색창과 필터에는 화면에 보이는 레이블 또는 명확한 접근성 이름이 있어야 한다.
- 상태는 색상 외에 텍스트로 표시한다.
- 외부 링크와 새 창 이동을 사전에 알린다.
- 월간 캘린더에는 동일 정보를 제공하는 날짜순 표 또는 목록이 있어야 한다.
- 포커스 링을 제거하지 않는다.
- 본문과 배경 명암 대비는 WCAG AA를 만족한다.
- `D-2`만 읽어도 의미가 통하지 않으므로 접근성 이름에는 대상 이벤트를 포함한다.
- 날짜는 스크린리더에서 연·월·일을 이해할 수 있도록 기계 판독 가능한 `datetime`을 사용한다.

## 15. 로딩·빈 상태·오류

### 15.1 로딩

- 초기 JSON 로딩 중에는 검색창과 주요 목록 위치에 스켈레톤을 표시한다.
- 전체 페이지를 스피너 하나로 막지 않는다.
- 로딩 중에도 헤더와 서비스 설명은 표시한다.

### 15.2 빈 상태

빈 상태는 이유와 다음 행동을 함께 제공한다.

```text
조건에 맞는 시험을 찾지 못했어요.
접수 상태 또는 기간 필터를 줄여 보세요.

[필터 초기화]
```

### 15.3 오류

- 수집 실패와 화면 로딩 실패를 구분한다.
- 수집 실패는 이전 데이터를 유지하고 신뢰 경고를 표시한다.
- 화면 로딩 실패는 다시 시도 버튼을 제공한다.
- 외부 링크가 없는 상태를 접수 마감으로 오해하게 만들지 않는다.

---

## 16. 문구 원칙

- 짧고 사실적으로 쓴다.
- 사용자가 해야 할 행동으로 버튼 문구를 작성한다.
- 기관 내부 용어나 데이터 필드명을 노출하지 않는다.
- 느낌표와 과도한 친근체를 사용하지 않는다.

### 16.1 권장 문구

| 상황 | 문구 |
|---|---|
| 검색 placeholder | `시험명 또는 시행기관 검색` |
| 공식 접수 | `원서접수` |
| 기관 상세 | `공식 시험정보` |
| 접수 중 | `접수 중 · 10월 19일까지` |
| 접수 예정 | `9월 21일 접수 시작` |
| 데이터 오래됨 | `마지막 확인 5일 전` |
| 미공고 | `아직 공식 일정이 발표되지 않았어요` |
| 면책 | `일정은 참고용이며 공식 공고가 우선합니다` |

### 16.2 날짜 표기

- 단독 날짜: `2026.09.12`
- 같은 연도 기간: `2026.09.21 ~ 10.19`
- 같은 달 기간: `2026.09.21 ~ 09.25`
- 목록의 짧은 날짜: `09.21 ~ 10.19`
- D-Day: 단독으로 쓰지 않고 `접수 D-2`처럼 대상 포함

## 17. URL·상태 보존

### 17.1 URL에 포함할 상태

- 검색어
- 카테고리
- 접수 상태
- 날짜 범위
- 일정 종류
- 정렬
- 캘린더에 선택한 시험 slug
- 보고 있는 달

### 17.2 URL에 포함하지 않을 상태

- 필터 시트 열림 여부
- 목록의 일시적인 hover·focus
- 자동완성 열림 여부
- 토스트 메시지
- 브라우저 로컬의 가정 날짜·목표 월·예약일

브라우저 뒤로 가기를 눌렀을 때 검색 결과와 스크롤 위치가 가능한 범위에서 복원되어야 한다.

## 18. 측정할 핵심 행동

분석 도구를 도입할 경우 아래 행동만 우선 측정한다.

| 행동 | 목적 |
|---|---|
| 검색 실행 | 사용자가 찾는 시험 파악 |
| 필터 적용 | 탐색 조건 이해 |
| 시험 상세 진입 | 검색 결과 유효성 |
| 공식 정보 클릭 | 서비스 핵심 전환 |
| 원서접수 클릭 | 가장 중요한 전환 |
| 통합 캘린더 진입 | 캘린더 표현의 실제 수요 |
| 캘린더에 시험 추가 | 복수 시험 비교 수요 |
| 캘린더 링크 복사 | 공유 가치 확인 |
| 계획 레이어 켜기 | 가정 날짜 기능의 실제 수요 |

검색어를 저장한다면 개인정보 안내와 보존 기간을 먼저 정의한다.

## 19. MVP 구현 우선순위

### P0

1. S-01 홈 검색과 이번 달 캘린더 미리보기
2. S-02 검색·필터·정렬
3. S-03 시험 상세의 월간 캘린더와 공식 링크
4. S-04 전체 일정 통합 캘린더
5. 출처·갱신 상태
6. 모바일 대응과 접근성 대체 일정표

### P1

1. S-04 시험 1~6개 선택 비교
2. 선택·필터·월이 포함된 캘린더 URL 공유
3. 시행그룹 중복 접기와 고빈도 일정 요약
4. 분야별 랜딩 개선

### P2

1. 기간 시행의 가정 날짜 표시
2. 상시시험 목표 월·예약일 표시
3. 캘린더 파일 다운로드
4. 최근 본 시험과 브라우저 로컬 관심 시험
5. 검색어 추천과 오타 보조
6. 연도별 과거 일정

P0가 완성되기 전에는 내 계획 레이어와 계정 기능을 추가하지 않는다.

## 20. 최종 검수 체크리스트

### 홈

- 첫 화면에서 검색창이 가장 먼저 보이는가?
- 전체 시험 목록이 처음부터 펼쳐지지 않는가?
- 현재 접수 중인 시험을 선택 없이 볼 수 있는가?
- 이번 달 주요 일정을 월간 격자에서 확인할 수 있는가?

### 탐색

- 검색과 필터 상태가 URL에 남는가?
- 시험명, 기관명, 상태, 날짜, 공식 링크가 한 행에서 연결되는가?
- 결과가 없을 때 필터 초기화 경로가 있는가?

### 상세

- 접수 중인지, 다음 일정이 무엇인지 첫 화면에서 알 수 있는가?
- 공식 정보와 원서접수 링크가 구분되는가?
- 출처와 마지막 확인일이 보이는가?
- 기간 시행이 월간 캘린더의 연속 막대로 보이는가?
- 상시시험에 존재하지 않는 확정 날짜를 만들지 않는가?

### 통합 캘린더

- 선택 없이도 전체 일정 모드가 동작하는가?
- 1~6개 시험을 선택해 같은 달력에서 볼 수 있는가?
- 같은 시행그룹의 중복 막대를 제거하는가?
- 모바일에서 가로 스크롤 없이 월간 날짜를 이해할 수 있는가?
- 기간 겹침을 위험으로 자동 판정하지 않는가?
- 공식 캘린더를 보기 위해 계획 입력을 요구하지 않는가?
- 공식 일정과 가정 날짜·예약일의 모양이 명확히 다른가?

### 공통

- 로그인 없이 모든 핵심 기능을 사용할 수 있는가?
- 오래된 정보와 수집 실패를 숨기지 않는가?
- 공식 공고 우선 고지가 있는가?
- 외부 이동이 명확한가?
- 색상 없이도 상태를 구분할 수 있는가?

## 21. 설계 결정 요약

| 이전 방향 | 새 방향 |
|---|---|
| 시험을 먼저 선택해야 일정 확인 | 선택 없이 전체 일정 탐색 |
| 개인 D-Day 홈 | 접수 상태와 공식 링크 중심 정보 허브 |
| 타임라인·줄글 중심 일정 | 월간 캘린더 중심 공식 일정 |
| 독립 일정 비교 페이지 | 통합 캘린더의 시험 선택 상태 |
| 필수 응시 예정일 지정 | P2의 선택적 가정 날짜·예약일 레이어 |
| 내 시험 관리 | URL 기반 캘린더 선택·공유 |
| 일정 충돌 판정 | 사용자가 캘린더에서 기간과 날짜를 직접 판단 |
| 로그인·저장 확장 | 로그인 없는 공개 정보 접근 |

이 문서에서 정의한 MVP의 성공 기준은 사용자가 시험 정보를 오래 머물러 관리하는 것이 아니라, **원하는 시험의 정확한 일정과 공식 경로를 빠르게 찾는 것**이다.
